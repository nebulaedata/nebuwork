## 使用入口

- 指挥官：`http://localhost:5173/#/workbench?tab=commander`
- 情报中心：`http://localhost:5173/#/workbench?tab=intel`

在页面顶部选择当前账号的工作台与项目。最近选择仅以账号隔离的 ID 偏好保存在浏览器；会话、Run、消息和成果保存在现有服务。前端没有写死以下环境 ID。

指挥官左栏可新建和切换主会话、发送目标、停止或补充执行；中栏读取用户、工作台、项目和配置专家的记忆；右栏查询授权项目任务、筛选状态并打开真实任务与成果。派发关系仅取成功工具结果中的任务 ID。点击“继续跟踪／回传成果”向原主会话提交请求。该按钮属于用户触发的智能体操作；看板可见时每 10 秒的刷新只读取任务元数据。

情报中心选择来源项目后，汇聚其项目/工作台知识引用和项目成果。选择资料、填写目标并点击分析，在独立情报项目创建并自动启动一次任务。成果使用项目 ID、成果 ID 和固定版本；跨项目文件不作为本项目附件提交。转交时先展示目标、接收会话、来源与分析成果引用，确认后发送到原指挥会话或新会话。

## 实现与契约

- `WorkbenchHub.jsx` 负责入口、目录和账号生命周期；身份版本变化即卸载旧页面，忽略迟到响应。
- `TaskConversation` 从现有任务页抽取，共用事件 reducer、Markdown、工具卡、附件、发送、命令和 SSE 恢复。原任务页三栏及成果预览保留。
- `MemoryPanel` 使用现有 scope/entry/task context 接口。图中只有真实配置归属、来源范围和记录的任务关系；没有数据时不画演示节点。加载更多、来源删除、停用、错误和实际使用记录分别展示。
- 情报资料使用现有 Knowledge scope/reference read 和 SourceNavigator；文件使用现有版本化成果预览。分页来源独立读取，单个来源失败不抹掉其他结果，保留内容会标记过期；权限拒绝时清除该来源的缓存。
- 引擎成果不保证有 `taskId`，按任务真实 session/run 关联，避免漏掉跨项目导入或误带其他任务成果。
- 已确认的转交建会话步骤不会因发送失败而重复创建；现有 API 封装保留不确定写入的幂等键。没有自动写入重放和后台周期触发。
- 自定义页面入口仅调用已有 API 封装。没有新增指挥官、情报、订阅或定时接口，也没有直连模型或知识基础设施。
