# 指挥官：系统问答、三维关系与用量诊断

交付日期：2026-10-19。本次替代指挥官原有的记忆中栏和任务右栏；情报中心及普通任务页继续复用原有业务能力。只修改前端和现有指挥官工作台配置，没有新增 HTTP/MCP 接口、数据库表或后端模块。Java、New2、Workflow 3.5 的代码和部署均未变更。

## 使用方式

打开 `/#/workbench?tab=commander`，选择已有工作台和项目。当前账号的选择 ID 会恢复，不写死业务 ID。

- 左侧“新建会话”只在绑定项目创建普通任务，首次发送后使用问题作为标题；追问在同一任务中追加 Run。切换绑定不会搬迁旧任务。普通问题可直接回答，业务查询使用已有授权工具，派发、控制和成果回传保留用户明确触发。
- 中间“系统关系”默认显示工作台、项目和专家，支持 Three.js 旋转、平移、缩放、搜索、类型筛选、选择、全景、聚焦、复位、应用内全屏及列表。WebGL 不可用自动降级为同一数据的关系列表。左栏宽度可拖动或用方向键调整；手机使用关系、统计抽屉。
- 点击项目并展开任务，每次增加 50 条，同时最多展示 200 个任务节点；统计始终使用完整授权目录。节点详情可看来源、执行详情、成果，或将查询目标填写到输入框，由用户发送。
- 右侧显示账号资源数量、任务状态、累计/今日实际 Tokens、近 14 日趋势、消耗前五和问题线索。可切换到对象范围；未知、部分已知、零和不可用分别展示。专家用量是独立维度，不加入系统合计。排名表示消耗较高，不判定异常。
- 成功工具的参数和结构化结果决定“本轮关联”，业务连线仍取真实记录。目录查询聚焦范围，具体对象优先；普通问答保留全景。刷新和历史切换从持久化事件恢复关联。

关系来源：工作台当前发布版本中的专家绑定、项目固定版本的专家配置、真实项目/任务归属、Run 的主专家/委派记录及持久化成功派发工具结果。配置关系使用虚线，归属和实际执行使用实线；不从当前配置或自然语言推断历史参与。专家参与详情按需加载，分页和加载不完整状态会明确显示。

## 数据刷新与隔离

共享目录、任务投影和用量在页面可见时每 10 秒只读刷新；详情最多 4 个并发，版本按 ID 缓存。没有后台模型调用或永久监控。临时失败保留最后成功数据并标记过期；401/403/404 清除对应可见数据。账号切换卸载旧页面，清空视图数据并忽略迟到响应。浏览器仅保存按账号隔离的选择 ID，不存业务正文、关系图内容或凭据。

前端将 API 的可变目录缓存复制为独立快照，避免任务/项目详情读取原地覆盖目录中的会话和用量。Three.js 独立延迟加载；刷新保留视角和选择，页面隐藏或容器不可见时暂停渲染，卸载释放资源。
