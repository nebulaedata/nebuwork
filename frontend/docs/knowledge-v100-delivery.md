# Nebulae V100 接入与管理员统一配置

本次同时修改 NebuWorkAgent、Java `nebuwork-backend-api` 和 NebuAgentCore。此说明取代旧文档中的个人/局部连接及知识工具未接通约定。

接口以本地 `nebulae-weknora/website-docs/04-api/03-external-integration.md`、`internal/router/routes_knowledge.go`、`routes_infra.go` 和对应 handler/types 为基线；[官方 API 概览](https://weknora.weixin.qq.com/docs/04-api/01-api-overview)。已适配 FAQ 双层分页、Wiki 原始对象和官方 CSV 中文表头。

## 使用

1. Nacos 设置 `nebu.knowledge.admin-ids`：统一用户服务账号 ID，逗号分隔，默认空名单。前端演示角色不参与授权。
2. 管理员进入“设置 → 知识库 → 管理员 · 知识库连接”，选择 **Nebulae V100**（`nebulae-v100-rest`），填写服务地址、API Key 和必要的空间 ID。根地址、部署子路径和 `/api/v1` 结尾均可；使用 `X-API-Key`、可选 `X-Tenant-ID`。
3. 勾选开放新建后，用户可通过连接创建自己的 document、faq 或 wiki 库。已有库由管理员“发现 / 分配”到明确账号。管理员配置权限不包含他人正文管理权。
4. “我的知识库”只返回本人创建、分配或历史授权的库。创建时选择远端已有模型和存储；类型及向量存储创建后固定。Embedding 仅在上游允许的空库条件下切换。
   向量存储留空或选择“使用空间默认向量存储”时，不发送 `vector_store_id`。上游 `__env_*` 是默认引擎的虚拟展示 ID，不能作为建库绑定；独立实例使用真实 ID。模型展示名为空时回退到模型名称。
5. “管理 / 详情”提供完整业务配置和内容管理。专家、工作台、项目保留紧凑引用卡片；新增知识库创建远端库，不再创建局部连接。

## 已实现功能

| 模块 | 操作 |
| --- | --- |
| 知识库 | 建库、详情、名称/说明、分块/索引、FAQ/Wiki 配置、模型和存储选择、引用检查及删除 |
| 文档 | multipart 上传、URL、Markdown 草稿/发布、手工正文编辑、分页/分块阅读、删除、重解析、取消解析、处理阶段和下载 |
| FAQ | 标准问、相似问、负样例、多答案、启停/推荐、标签、批量维护、CSV/JSON 导入导出、异步校验、进度和错误明细 |
| Wiki | 页面、目录、移动、搜索、分页索引、统计、关系图、历史版本/恢复、链接重建、一致性检查/修复和问题状态 |
| 引用 | 单连接 + 单远端库，工作台发布冻结引用、项目继承只读，远端内容实时读取，Core 仅检索和阅读 |

上传上限 100 MiB，仍受部署的 Spring multipart 限制。CSV 兼容官方中文列及 `##` 分隔，也支持英文字段；JSON 导入去除导出 ID。Wiki 编辑带版本号。删除、FAQ 替换导入、Wiki 恢复及修复均有影响确认。

活动内容列表、导入进度和待恢复操作每 3 秒刷新，最多 5 分钟；导航、账号切换和关闭弹窗终止请求，迟到响应不覆盖新界面。上游认证错误不会注销本站登录。旧 Nebulae V1 HTTP 保留原只读能力，不提供 REST 写入入口。

## 接口与安全边界

浏览器继续访问 `/nebulaedev/nwaa/api`，远端访问全部由 Java 执行。保留 `/knowledge-mcp` 和 `/knowledge-scopes` 前缀。

| 接口 | 用途 |
| --- | --- |
| `GET /knowledge-mcp/settings` | 当前账号 `canEdit`、账号 ID |
| 原连接新增/更新/测试/删除 | 仅管理员；浏览器更新使用 POST |
| `GET /connections/{id}/discover`、`POST /connections/{id}/assign` | 管理员发现和明确分配远端库 |
| `POST /connections/{id}/manage` | 固定 `operation`、`collectionId`、可选 `resourceId` / `payload`，逐次检查归属 |
| `POST /connections/{id}/upload` | multipart：file、fileName、collectionId、requestKey |
| `POST /connections/{id}/download` | 库内原文件或 FAQ CSV/JSON，返回附件流 |
| `GET /operations`、`POST /operations/{id}/recover` | 本人回执与恢复，不重发远端写入 |
| `GET /operations/{id}/progress`、`POST /operations/{id}/errors` | 检查本人、库归属和已记录任务 ID 后读取进度/错误报告 |

表中连接和操作接口位于 `/knowledge-mcp` 下。没有任意 URL/方法代理，也不接入远端用户、模型密钥、基础设施或聊天管理。模型/存储目录仅返回名称、ID、类型。正文、任务及下载检查归属；管理员普通目录仍受内容权限限制。只读接口和 Core 工具新增可选 `contentKind`、`page`、`pageSize`，兼容旧调用。

写入使用稳定 `requestKey` 和请求摘要；Java 不重试写入。响应丢失保留 `sent`，需核对结果。建库响应先独立保存 `received`，再登记归属；登记失败由原发起者恢复，管理员不能将待恢复库分给其他账号。成功为 `completed`。操作列表不重新暴露缓存正文。完整错误报告由 Java 校验归属并按网络策略下载，不向浏览器直接暴露签名 URL。

## V15 迁移

新增 `V15__knowledge_administration.sql`，V1–V14 未改动：

- 连接增加开放新建、空间及历史回填标记。旧连接 ID、原 owner、密文、引用和发布快照保持不变；旧连接默认不开放新建。
- `nw_knowledge_library` 按规范化服务地址与远端库 ID 唯一登记所有者；重复连接不能产生第二个所有者。
- `nw_knowledge_library_access` 从草稿和发布快照回填历史只读权限。一次性完成标记防止再次授予已撤销权限。未引用库等待管理员分配。
- 历史同库多账号引用保留只读。管理员可明确分配首位内容所有者，其他历史读权限保留；已有所有者之间的转移受引用保护。
- 旧密文仍使用原 owner 作为 AES-GCM 加密身份，新连接用系统身份；管理员响应也不返回明文。
- `nw_knowledge_operation` 保存回执；全局引用保护涵盖同一服务下所有连接的草稿、发布版本和项目继承。普通用户仅查看自己的引用详情，其他账号只显示阻止原因。

部署前保存数据库备份和原知识库加密密钥；先部署 Java 并由 Flyway 执行 V15，再更新前端/Core，设置管理员名单，最后分配或开放连接。不要更改旧迁移校验和，不要通过修改 owner 来迁移配置管理权。

# V16 管理员模板与 AI 一键创建（2026-10-14）

新增“设置 → 知识库 → 连接 → 创建模板”和“我的创建任务”。管理员维护多个模板、版本、启停和一个默认模板；用户只选择可用模板、输入业务描述及可选名称。技术参数由模板确定，不向普通用户展示服务地址或凭据。

默认创建 document，同时启用向量/关键词 RAG、Wiki、知识图谱和图像理解。分块默认 1000/200，Wiki 为标准粒度；图片向量和语音仍是独立的可选功能。原手动 FAQ / Wiki 创建和已有知识库引用保留。

“AI 一键创建”提交后台任务；“先预览配置”允许编辑生成的名称、简介、Wiki、图片和图谱业务要求。用户原先输入的名称优先保留。图谱示例在预览中标明为虚构，不作为真实资料上传。成功后进入知识库详情，展示远端实际生效能力和业务配置；引用失败保留已创建的知识库。

进度显示依赖检查、生成、校验、创建、回读和登记的真实阶段。每 3 秒刷新，5 分钟后改为手动刷新；页面关闭、导航和账号切换停止请求并忽略迟到响应，后台继续执行。任务可在“我的创建任务”重新打开，失败生成可重试，创建结果不明只能核验原库并恢复登记。

三个项目按 WeKnora → Java V16 迁移 → 前端顺序部署，模板校验并启用后才向用户开放。Java 的 `README-knowledge-creation.md` 包含接口、权限、恢复语义和代理超时说明。900 秒生成窗口只用于 Java 到 WeKnora 的生成请求；浏览器不等待长连接生成。NebuAgentCore 无改动。

本次交付保留原工作区修改和已有服务，正式数据库的迁移及运行进程更新需随部署执行；隔离数据库的 V1–V16 已通过自动测试。旧版本 Java 返回新接口 404 表示尚未完成服务更新。

## 批量与文件夹上传（2026-10-15）

设置中的知识库列表和详情、专家与工作台的知识库区域共用上传流程。支持多选文件、文件夹递归导入、目标库选择、大小/路径预检和移除待上传文件。专家和工作台仅显示已引用且当前账号可管理的文档/Wiki 库；FAQ 保留导入流程。

应用顶部“上传任务”展示账号会话内共享队列，串行提交每个文件。关闭弹窗或站内导航后继续；刷新页面停止剩余任务，退出或切换账号会中止请求、释放文件引用并清空队列。可停止每批剩余文件，当前请求保留其回执。逐文件区分等待、上传中、已接收、已存在、失败、结果待核对和已停止；单文件失败继续，目标权限失效停止该库后续上传。文件仅驻留内存，远端接收与解析完成分开展示，不自动重传写请求。

上传接口仍为 POST /knowledge-mcp/connections/{id}/upload，multipart 原字段 file、fileName、collectionId、requestKey 保留，新增可选 relativePath。Java 在回执创建前验证非空、100 MiB 上限、相对路径安全、最多 16 层目录、目录段最多 128 UTF-8 字节及目录路径最多 1024 字节。文件附件头只包含基础文件名，相对路径通过远端 fileName 字段保存到既有 folder_path。旧单文件幂等摘要保持不变；新请求将规范化路径纳入摘要。

响应增加 outcome=accepted/duplicate。只有远端明确的 duplicate_file 冲突被转为已存在回执，保留原文档和原路径；其他冲突及超时仍需核对。重复回执校验知识库归属且只保留必要文档字段。目录/正文读取补充 folderPath、fileName；管理页与只读浏览窗口显示来源路径，目录可显示实际解析状态。后台文件上传不会使正在加载的专家/工作台定义失效。

验证：前端知识库、上传队列、API、专家和工作台相关回归共 75 项通过；类型检查通过。Java 知识库专项 76 项通过，1 项真实远端联调用例按默认配置跳过；使用本机 Java 8 和 IPv4 配置运行，隔离 H2 执行现有 V1–V20 迁移，JAR 打包通过。浏览器通过本地隔离模拟 API 验证三处入口、多文件/文件夹、不同目录同名文件、跨页面继续、重开队列、停止剩余、账号切换、路径/状态展示及 390px 窄屏。浏览器模拟解析状态不能替代真实远端解析验收。

无新增迁移，无 Core 或远端 Go 源码改动。先部署新版 Java，再部署前端；现有业务服务未重启，正式数据库未修改。真实远端解析需在目标隔离知识库完成联调。
