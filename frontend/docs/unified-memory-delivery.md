# Hindsight 五层记忆交付说明

本次修改覆盖 NebuWorkAgent、Java nebuwork-backend-api 和 NebuAgentCore。功能默认关闭；没有执行数据库迁移、测试、构建、服务重启或真实记忆写入。上线前须由使用方完成下列验证。

## 范围与入口

| 类型 | 入口 | 读取范围与发布方式 |
|---|---|---|
| 用户 | 设置 → 我的记忆 | 当前账号所有任务；本人维护，提升内容审核后发布 |
| 任务 | 任务右侧 → 任务记忆 | 仅当前任务；收齐终态事件后自动生成来源 |
| 项目 | 项目 → 记忆 | 当前项目任务；成功轮次按独立规则筛选项目事实 |
| 工作台 | 工作台配置 → 工作台经验 | 当前账号使用此工作台的任务；审核后发布 |
| 专家 | 专家详情 → 经验记忆 | 当前账号且固定模板包含该专家的任务；审核后发布 |

专家定义可以共享，账号记忆 Bank 不共享。不同任务与项目不能直接读取彼此范围。提取来源包含明确的用户陈述、助手报告、执行状态、待办及成果引用；助手完成任务不代表其结论已经核验。来源处理完成可能没有提取出任何事实，详情展示可追溯的已提取事实（最多 50 条）。

用户确认提升至项目后直接排队同步；提升至用户、工作台或专家范围先保存待审核草稿。自动来源提升时不会预填整轮材料，用户填写已确认事实，或从检索结果选取事实再编辑。工作台、专家以及需要审核的提升/建议条目编辑后重新进入审核。审核发布不会改写 SOP、模板、系统提示词或知识库。

## 运行与同步

- Java 在创建新 Run 时固定允许范围，提交 Core 前并行召回并落库存档；重试提交和恢复沿用原快照，新 Run 重新召回。
- 默认召回网络总截止 3 秒、预算 3,000 tokens。首期按序列化结果的 UTF-8 字节数做保守上界，因此实际可容纳 tokens 少于上限；优先任务、项目，其次用户、工作台、专家。Core 再按整体上下文余量保留完整事实，`memory.used` 记录实际注入的版本。
- `memory_search` 只能检索该 Run 允许且仍有权限的范围，每次检索单独审计。`memory_propose` 只创建草稿，沿用现有工具审批权限；幂等编号使用持久化工具调用 ID。
- `autoMemoryBackflow` 偏好控制智能体是否主动建议专家经验；关闭后仍可按用户明确要求提交草稿，任何模式都不能自行发布。
- Hindsight 不可用或旧 Core 无能力声明时，页面显示不可用/部分召回/不支持，普通任务继续执行。空集合不会掩盖网络故障。
- MySQL 维护来源、版本、审核、作业和召回审计，Hindsight 按范围独立 Bank 提取和检索。只接收匹配账号、范围、文档 ID 和有效同步版本的 world/experience 事实，观察/反思及无法核验的结果不注入。
- 编辑、停用、删除后，新检索立即排除旧版本。已固定的执行快照与历史审计仍保留；不会中途改写运行中的上下文。
- 同条目同步按顺序执行，固定 document_id 和 operation_id。网络故障自动退避重试；配置、不可重试错误及反复失败的提取显示失败，修复后可手动重试。
- 删除任务只清理其任务记忆，项目和审核发布的经验独立保留并显示来源任务删除状态。“我的记忆”提供尚未完成的清理记录，包括已删除任务。
- 仅对启用后新创建的 Run 自动沉淀；不回溯历史聊天、文件或本地 `.nebu/memory.md`。停用功能保留待处理同步作业，重新启用后继续。

## 部署顺序（使用方执行）

1. 备份业务数据库，由使用方安排 Flyway 顺序执行 Java `V12__unified_memory.sql`、`V13__memory_settings.sql`（原 V1–V11 保持不变）。当前 Java 启动会自动调用 `flyway.migrate()`；V12/V13 已按用户要求改为可重复执行，支持手工先刷同一套表结构后再由 Flyway 补登记。已有表和 V13 配置值保持不变；失败记录不会因手工建好表而自动消失。
2. 部署 Java、支持 `managed_memory_version: 1` 的 Core 和前端；初始保持记忆关闭。
3. 在 Nacos 的 `nebu.memory.admin-ids` 指定有权修改全系统记忆配置的统一用户 ID（逗号分隔）。普通账号在记忆设置页面可看到本人 ID。管理员进入 **设置 → 记忆设置**，维护启用开关、服务地址、访问密钥、召回总超时、同步超时及召回预算；REST 地址为 `http://192.168.77.152:8888`，当前无访问认证，密钥留空。Hindsight 调用模型的密钥不填在这里。保持现有 `nebu.core.instance-id` 稳定，它参与 Bank 映射。
4. Core 继续使用既有 `NEBU_BUSINESS_API_BASE_URL` 与独立的 `NEBU_BUSINESS_API_KEY` 服务认证；无需直连 Hindsight，也无需新增 Core 数据库迁移。浏览器仅通过既有 Java 网关。
5. 使用方运行三端测试和构建，再在页面打开记忆开关，用测试账号完成真实提取与召回验收。回滚时先在页面关闭记忆开关，普通任务继续运行；无需删除记忆表。

## 页面配置

若手工执行本仓库 V12/V13 后，Java 提示 `Detected failed migration to version 12`：保持 Java 停止并备份迁移历史，重新构建后端以更新包内 SQL，然后执行后端 `nebuwork-backend-api/scripts/Reset-FailedMemoryMigrations.sql` 清理已知的 V12/V13 失败记录。无未知失败/校验和提示时再启动，由 Flyway 重放可重复执行的 SQL 并登记成功。业务表和数据不会被清理。

该处理脚本不修改成功记录；已经成功应用旧 V12/V13 的环境会因脚本改动产生校验和差异，需要先通过 `Inspect-MemoryMigration.sql` 核实表结构，再由使用方执行 Flyway repair。已有表跳过创建不代表会补齐另一套同名表的字段/索引。不要直接标记成功、删除成功历史或关闭校验。新增 `MemoryMigrationIdempotencyTest` 供使用方验证重复执行和数据保留，本次未运行测试、SQL 或服务重启。

“记忆设置”管理全系统服务，“我的记忆”维护本人条目。后端校验指定管理员身份；普通账号只能看到启用状态，不得到服务地址和凭据。前端不依赖演示用户角色授予权限。密码不回显、不写浏览器存储；留空保留，明确勾选才清除。更换账号或离开页面会清空密钥输入并丢弃迟到响应。

配置与无密钥的变更审计持久化到 MySQL，保存后后续请求立即使用；运行中的固定快照不替换。首次保存前 Nacos 同名参数仅作默认值，保存后不再覆盖页面配置。仅管理员名单和凭据加密主密钥仍在部署侧维护；有访问密钥时沿用 `nebu.models.encryption-key` 加密，无认证部署无需配置它。

测试连接只由 Java 请求当前表单地址的健康接口，不保存配置、不写入记忆，也不表示访问密钥或提取/召回效果已经验证。保存失败保留输入；不修改输入直接重试会沿用请求编号，避免响应丢失导致重复保存。版本冲突明确提示重新加载，不静默覆盖。

已有记忆范围（包括草稿）后地址只读，避免切换 Hindsight 实例使 Bank 或待同步操作丢失；远端数据迁移不在页面范围内。开关、密钥、超时和预算仍可修改。
