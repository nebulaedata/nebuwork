## 1. 产品目标与已确定要求

NebulaeKno 是可独立部署的知识库处理与检索服务，附带中文管理页面。管理页面和其他项目使用同一套 HTTP API。

| 项目 | 确定方案 |
| --- | --- |
| 产品名称 | NebulaeKno |
| 服务、镜像和目录命名 | nebulaekno |
| 前端技术栈 | React + TypeScript + Vite；TDesign React 作为统一后台 UI 组件库 |
| 页面风格 | 参考已有前端的字体、字号、绿色主题与页面密度；基础控件直接使用组件库及其公开主题配置 |
| 环境变量前缀 | NEBULAEKNO_ |
| 使用方式 | 先创建知识库，再向知识库上传和管理文档 |
| 访问方式 | 无登录、无调用方 Token、无接口 API Key；所有调用方共享公共知识库 |
| 核心处理能力 | 上传、解析、文件目录结构树提取、分块、OCR、图片描述与属性识别、音频转写、视频字幕与画面处理、索引、知识图谱、Wiki |
| 默认启用 | 文件目录结构树提取、关键词索引、向量索引、Wiki 生成、知识图谱抽取 |
| 默认语言 | 简体中文；OCR 忠实保留原文语言 |
| 检索能力 | 关键词、向量、混合、图谱、Wiki、图片文字、图片语义、多路综合检索 |
| 来源追溯 | 各类召回结果携带可验证的源文件和位置引用 |
| 文件预览 | 原文件、格式渲染、转换副本与解析内容预览；实际支持格式、定位能力和降级原因可查询 |
| 音视频 | 正式入库；转写/字幕及视频画面参与检索，结果定位到源文件的时间段或帧位置 |
| 交付方式 | 一个应用镜像、一个应用容器与文件数据卷；连接用户已部署的三项固定外部中间件 |
| 中间件 | PostgreSQL + pgvector、Neo4j Community + 匹配的 APOC Core、Redis；不做数据库类型切换或备用数据库回退 |
| 部署配置 | 三项连接 URL 通过环境变量提供；不在后台页面修改基础设施连接 |
| 启动条件 | 必需配置、连接、权限、扩展、初始化、迁移与关键能力检查全部成功后才进入 ready |
| 模型运行位置 | 通过设置页接入外部或宿主机模型服务，模型推理服务不默认装入应用容器 |

公共访问包括知识库、文档、Wiki 和设置的读取与修改。后台不设置用户、角色、租户选择或授权流程。内部可保留一个固定公共空间，以适配已有知识库与文档的数据关联；调用方不需要传空间或用户标识。

## 2. 主要工作流程

首次部署：准备固定中间件 → 配置三个连接 URL → 启动应用容器 → 自动校验、建库/建表/建索引与初始化 → 就绪后进入设置页 → 添加和测试模型 → 绑定模型用途 → 保存默认处理配置 → 创建知识库。

日常使用：选择知识库 → 上传文件 → 自动解析 → 图片观察/描述、可选矫正与 OCR → 汇总可检索文本并分块 → 建立关键词、向量索引 → 自动抽取知识图谱并生成 Wiki → 在召回测试页检查结果 → 点击来源查看原文。

音视频上传进入专用分支：媒体探测 → 音轨/字幕选择 → 分段转写与时间校验；视频同时抽取代表帧并进行 OCR/画面描述 → 建立保留时间来源的分块及索引 → Wiki/图谱 → 搜索命中后跳转播放。音频、视频均沿用“先建知识库、再上传”的同一文档体系。

每个文件增加自动目录提取阶段：原生结构或解析正文就绪后生成候选章节树，按准确性要求使用文本/视觉模型提取和校验，再验证原文位置；扫描件所需 OCR 完成后补做。目录提取可与分块和后续索引并行，保存独立状态，不依赖向量模型、Wiki 或图谱生成。

模型尚未配置时，在中间件及初始化检查均成功的前提下，允许进入设置页、创建知识库和保存文件。需要该模型的处理阶段显示“待配置”，保存具体原因；模型就绪后可继续任务。数据库或中间件配置错误则启动失败，不能降级为本地库或缺少图谱/队列的运行模式。

Wiki 与图谱可以并行生成。文档、图片、索引、Wiki、图谱各自记录状态，允许出现“文档可检索，Wiki 仍在生成”等真实中间状态。

### 3.1 知识库列表与详情

知识库列表默认采用表格，适合按状态和时间比较多个知识库。名称旁显示类型和状态，操作集中在行尾。主要按钮为“新建知识库”，上传作为选中知识库后的动作。

新建知识库只要求名称。其他配置继承全局默认值，包括模型绑定、目录提取、分块、图片处理、Wiki、图谱模板和检索参数；可展开高级配置覆盖。

知识库详情顶部显示名称、简介、处理状态和主操作。下方采用以下页签：

| 页签 | 具体设计 |
| --- | --- |
| 文档 | 文件夹目录、文件列表、处理阶段、文件类型、标签、更新时间；文档行显示内部目录提取状态 |
| 分块 | 按文档筛选、父子块关系、正文、标题路径、原文位置；可编辑、停用、查看版本 |
| 图片 | 缩略图、OCR 文本、描述、属性、来源文档；点击进入图片和原文对照 |
| Wiki | 目录树、页面正文、反向链接、引用来源、修订历史；支持编辑和回滚 |
| 知识图谱 | 实体与关系画布、名称搜索、关系过滤、邻居展开、证据列表 |
| 设置 | 当前知识库的模型、解析、分块、索引、图片、Wiki、图谱和检索配置 |

全局默认值变更只影响之后新建的知识库。已有知识库保留自身配置；应用新默认值必须明确执行，并展示是否需要重新解析、重新生成或重建索引。

### 3.2 上传页面

页面先选择知识库，再选择文件或文件夹。目标知识库未选择时显示清晰的选择入口，避免产生无归属文档。

上传区下方展示文件名、大小、目录、上传状态、解析状态。批量上传保留逐文件结果，单个失败不阻断其他文件。

默认使用知识库配置。“本次处理设置”可覆盖解析引擎、分块、图片处理、音视频转写/音轨/画面处理、Wiki 和图谱开关。任务启动时保存配置快照，之后修改全局设置不会改变正在运行的任务。

处理轨迹包括：上传、解析、图片处理/OCR、文件目录提取、分块、关键词索引、向量索引、Wiki、知识图谱。音视频额外显示媒体探测、转写/字幕、抽帧、画面识别与播放副本准备的独立状态。进度按实际完成量展示，没有准确分母时显示阶段和已处理数量。

上传确认和重新解析都显示“本次实际使用的解析引擎、图片流水线、预处理模式”。按格式选择引擎的结果由后台解析配置接口返回；页面不能显示一个引擎，任务却实际执行另一个。批量状态优先使用事件流，退回轮询时限制并发，切换文档后丢弃旧请求响应。

### 3.3 文档与原文定位页面

采用双栏对照：左侧原文件预览或音视频播放器，右侧解析文本、分块或当前召回结果。点击来源后，左侧跳转到对应页、表格区域、段落、图片位置或播放时间，右侧显示匹配内容与上下文。

界面同时显示文件名、文件版本、页码或位置、定位精度。匹配区域与上下文区域使用不同的高亮样式，避免把补充上下文误认为直接命中。

来源有多个位置时，显示位置列表，如“第 3 页、第 4 页”，逐项切换。定位失败时保留可用的原文件、版本和较粗位置，明确显示原因。

原文件预览区增加可折叠的“文件目录”栏，宽屏宽度约 240px；点击节点通过统一来源接口跳转章节起始页或段落。窄屏使用抽屉，保留原来的文件/结果对照空间。目录标题旁显示页码或位置，未定位成功的条目不提供虚假跳转。

文件详情和召回结果共用预览组件，提供“文件预览 / 解析内容”切换。预览栏标明原文件、格式渲染或转换副本，提供目录、页码/工作表/章节切换、缩放、全屏及下载；格式支持范围详见第 15 节。

### 3.4 Wiki 页面

宽屏采用目录、正文、引用信息三部分；引用侧栏可折叠。正文默认阅读态，编辑进入独立状态，离开未保存内容时提示保留或放弃。

提供自动生成、增量合并、人工编辑、修订历史、版本比较和回滚。引用来源支持跳转原文件的具体位置。

人工编辑与自动生成内容都要保留版本。重新生成前展示作用范围，避免无提示地覆盖人工修改。文档删除或更新后，将受影响引用标为失效或待更新，再按规则处理相关页面。

Wiki 页面关系图和知识图谱分别展示：前者反映页面引用，后者反映从文档抽取的实体与关系。

扫描件必须等待有效 OCR 文本就绪，再生成 Wiki。正文只有图片链接时，读取对应的 image_ocr 分块并去重；无有效文字时显示“等待 OCR”或“可读内容不足”，不生成看似完整的 Wiki。生成页面中的事实引用仍指向扫描件原页。

Wiki 链接图增加主题分组、分组聚焦和返回全图。表格更新需检查原有行是否丢失，自动合并产生重大内容减少时标记冲突并保留旧修订。

### 3.5 知识图谱页面

画布支持缩放、拖动、选中实体、展开一至两跳邻居。默认只加载有上限的局部图，避免首次打开整个知识库的全部节点。

选中实体或关系后，侧栏展示名称、属性、关系类型、来源文档和证据片段。每条证据都可打开源文件对应位置；同一实体在多个文件出现时保留多条来源。

### 3.6 召回测试页面

顶部选择知识库，可进一步限定文档、目录、标签和文件类型。查询区提供文本输入；图片语义检索可上传查询图片或选择已有图片。

模式使用中文名称，旁边显示简短说明。高级参数包括候选数量、返回数量、重排、上下文补齐、图谱跳数和诊断输出。

结果区采用连续列表，单条包含：标题、匹配片段、命中方式、分数类型、原文件与位置、查看原文。图片结果附缩略图，Wiki 结果附页面入口，图谱结果附证据关系。

侧栏或下方诊断区展示各路耗时、候选量、融合结果、重排状态、跳过原因和索引就绪状态。分数显示其含义，不显示为“答案正确率”。

对比模式并排展示不同检索方式的结果、来源、耗时和重合情况。复制请求参数使用页面真实参数，方便其他项目复现。

增加“能力就绪”提示：每种检索显示可用、待建索引、待绑定模型或依赖不可用。诊断区展示截断原因、图片向量覆盖范围与未重建文档数；避免将索引不完整误认为源资料不存在。

### 3.7 图片处理设置与详情

设置页、知识库设置和上传确认共用一个图片处理面板，按“处理方式 → 常用选项 → 高级参数”排列。控件来自后台流水线元数据；不同页面使用相同字段和校验规则。

| 区域 | 页面设计 |
| --- | --- |
| 处理方式 | 智能处理 smartocr：先观察与描述，再决定是否 OCR；手动处理 default：明确选择描述、OCR 等动作 |
| 页面预处理 | 关闭 off、自动 auto、总是尝试 always；当前智能流水线支持该步骤，其他流水线按能力决定是否显示 |
| OCR 兜底 | 无法判断文字属性时是否仍执行 OCR，默认开启 |
| 高级参数 | 观察、描述、OCR 各自的思考开关；默认关闭，只有所选流水线实际使用的参数可编辑 |
| 图片详情 | 原图、处理后图片、OCR 原文、中文描述、属性、处理轨迹、来源页与定位精度 |
| 失败与跳过 | 分别显示观察、预处理、OCR 的结果；如“矫正失败，已用原图识别”“无文字，跳过 OCR” |

预处理前后可以并排对照，始终提供原图入口。矫正产物是派生版本，不覆盖原图；重做 OCR 前展示将更新的图片文本索引与受影响 Wiki。

### 3.8 解析质量与格式设置

默认解析设置增加“HTML 正文提取”“Excel 百分比显示”“保留表格结构”和按格式的引擎覆盖。旁边提供单文件试解析，查看实际引擎、文本、表格、图片和来源映射。

HTML 可选择全文或正文优先，正文提取失败时回退全文并说明原因。Excel 展示值与底层数值同时保留，例如显示 25%、原始数值 0.25，避免百分比语义丢失。CSV 多行单元格、JSON 大整数及 HTML 表格中的竖线列入解析样例。

### 3.9 任务中心与运行状态

列表展示业务任务与子阶段，详情提供时间线、有效配置、失败类别、重试记录和来源对象。刷新页面后可以继续观察同一 task_id；事件流重连从 last_event_id 续接。

取消先显示“正在取消”，待实际停止后标记“已取消”。模型参数错误、无效图片等永久失败不反复重试；模型临时不可用、限流等错误按预算重试。阶段部分产出应显示部分成功，不能仅因主任务结束就把所有阶段染成绿色。

运行状态增加预处理服务、中文分词、图片向量能力及图谱写入依赖。模型测试除连通性外，还要验证一次最小能力请求的返回结构。

数据库和中间件连接属于部署环境配置，页面只显示脱敏后的服务标识、版本、连接状态和迁移版本，不提供数据库类型选择或连接 URL 修改入口。初始化失败时从容器日志查看具体阶段和原因；正常业务页面不会在依赖未就绪时开放。

音视频状态另列 FFmpeg/ffprobe、实际编解码能力、ASR 分段时间戳能力、画面 OCR/描述模型和播放副本生成能力。缺少 ASR 时保留原文件并等待配置；视频已完成的字幕或画面索引仍可单独使用。

### 3.10 中文配置辅助生成

保留旧项目已有的配置生成方向：在新建知识库和设置页，根据名称、简介、业务要求生成 Wiki 指导、图片描述指导、图谱抽取示例与中文关系标签。

结果先进入草稿，展示与现有配置的差异，点击“应用草稿”才保存。生成结果不能自行替换模型 ID、存储、鉴权或功能开关；图谱示例必须通过节点唯一、关系引用完整等结构校验。无需模型即可使用内置 general-zh-CN 模板。

### 3.11 每个文件的目录结构树

文件上传后自动提取目录，在文档详情中展开树状展示。区分三个已有导航范围：知识库的文件夹列表、当前文件的章节目录、Wiki 的页面目录；新增目录属于当前文件。

目录栏提供展开/收起、本地标题过滤、刷新状态、重新提取和导出结构 JSON。默认展开前两级，节点保持源文件顺序和原始标题语言。显示“提取中”“等待 OCR”“等待媒体解析”“已完成”“部分完成”“未识别到目录”或“提取失败”。

每个文件都有目录状态。无可识别章节时，仅显示文件根入口和空状态；Excel 可以展示工作表，PPT 可以展示已有节与幻灯片标题。允许大模型识别和纠正有原文依据的标题与层级；不生成无依据主题或章节摘要。

增加“已核验 / 待核验 / 无法定位”标记与简短原因，默认只展开层级清晰的两层。设置页可选择自动使用模型、总是模型复核或仅结构提取，并显示实际模型与处理预算；默认准确性优先。待核验项提供原文对照与重新核验入口。

### 3.12 音视频详情与设置

详情页采用“目录/章节 + 播放器与时间线 + 转写/字幕”的布局。支持倍速、时间跳转、上一条/下一条命中、播放命中片段、字幕开关与逐句跟随。视频增加画面缩略图轨道，点击识别出的画面文字或代表帧跳到原视频对应时间；原帧 OCR 框在静止帧上高亮，不作为持续跟踪框显示。

结果卡展示文件名、时间区间、命中文本、证据类型及视频缩略图。真实命中区间与前后播放上下文使用不同样式。多音轨、字幕语言及可用的匿名说话人标签分别显示；无说话人识别结果时不猜身份。

设置页新增“音视频处理”：ASR 模型与语言、音轨选择、字幕优先策略、带时间的分块、画面采样/OCR/描述、播放转换、文件/时长限制与任务预算。详情页可以分别重做转写、重提画面或重建播放副本，不强制整份文件从头重跑。

### 4.4 组件库使用规则

基础交互必须直接使用 TDesign React：按钮、输入框、下拉、表单校验、开关、表格、分页、树、上传、弹窗、抽屉、菜单、提示、标签及状态反馈。不使用原生 button/input/select 再手写一套皮肤，不通过改写组件库源代码实现页面风格。

允许三类前端工作：组合组件形成业务页面；通过组件公开属性与插槽/渲染函数表达业务；通过官方 Design Token/CSS Variables 统一设置颜色、字体、圆角和尺寸。页面布局 CSS 仅负责区域宽度、网格、间距、滚动和响应式；不深度覆盖组件内部 DOM，不堆叠 `!important` 重做基础控件状态。

TDesign 的官方主题方案使用 CSS Variables，并提供颜色、字体、圆角、阴影及尺寸等 token；新项目在统一主题入口配置这些变量。[TDesign 官方主题说明](https://github.com/Tencent/tdesign-common/blob/develop/docs/web/theme.md)

应用自定义 token 使用 `--nebulaekno-*`，组件库公开的 `--td-*` 保留其标准名称。ConfigProvider 负责中文语言及公开的全局组件配置；主题颜色与字号使用文档支持的主题变量，不假设存在未验证的配置字段。

基础控件默认采用组件库 medium 尺寸，密集表格工具栏可用 small，大尺寸只用于明确需要的入口。表格沿用组件库的密度、行高和内边距配置，多行内容自然增高；不硬写统一行高导致文字被裁切。图标统一使用 TDesign React 图标，通常为 16/20px，并提供必要的文字提示。

仅保留一套后台基础 UI 库。文件渲染、媒体播放和图谱属于专业展示能力，可接入相应成熟库；其外部工具栏、设置、错误提示和来源信息继续使用 TDesign React。

## 5. 召回与搜索设计

### 5.1 检索方式

统一入口为 `POST /api/v1/search`，由 `mode` 指定检索方式。各方式共享范围过滤、来源引用和结果结构。

| mode | 中文名称 | 行为 | 依赖与说明 |
| --- | --- | --- | --- |
| keyword | 关键词检索 | 对标题、正文、OCR、转写和字幕等可检索文字进行中文分词与全文检索 | 应用侧中文分词 + PostgreSQL 全文检索；独立使用时不要求向量模型 |
| vector | 向量检索 | 将查询转为向量，召回语义相近分块 | 文本向量模型及 PostgreSQL pgvector 索引 |
| hybrid | 混合检索 | 并行执行关键词和向量召回，去重并融合 | 默认方式；融合后可选重排 |
| graph | 知识图谱检索 | 定位实体，沿关系查找证据，再返回关联原文 | 图谱索引；名称匹配可直接运行，语义实体识别可按需使用模型 |
| wiki | Wiki 检索 | 检索页面标题、别名、摘要和正文，返回页面与引用 | 默认全文检索；页面向量检索需另建页面索引 |
| image_text | 图片文字检索 | 检索图片及视频代表帧的 OCR、描述和可检索属性 | 返回图片与来源；视频帧同时关联原视频时间；不代表理解视觉相似性 |
| image_vector | 图片语义检索 | 文本找图或以图找图，包含已索引视频代表帧 | 需要多模态向量模型及图片/帧向量索引；命中视频帧可回到播放时间 |
| multi | 多路综合检索 | 在明确选定的多个通道间召回并融合 | 默认组合可为 hybrid、wiki、graph、image_text |

关键词索引与向量索引要分别实现就绪判断。纯关键词检索不能被向量模型缺失所阻断。

关键词路径固定为应用侧统一中文分词、PostgreSQL tsvector/tsquery 与 GIN 索引，默认排名标识为 pg_ts_rank_cd。索引和查询使用同一分词器及词典版本，原文位置继续从 source_blocks 映射；不要求额外安装数据库中文分词扩展。PostgreSQL 原生全文排名与 BM25 不同，响应不得混用名称。[PostgreSQL 全文检索文档](https://www.postgresql.org/docs/17/textsearch-controls.html)

`image_vector` 所需的多模态向量模型与 OCR 使用的视觉模型是不同用途，不能根据“支持看图”就认定模型支持图片向量。

重排是召回后的可选步骤，不作为独立召回模式。文本重排可处理分块、Wiki 正文和图片的文字描述；图片视觉重排需专门模型，不能冒充文本重排结果。

### 5.2 通用请求参数

| 参数 | 说明 | 建议默认值 |
| --- | --- | --- |
| query_text | 文本查询；关键词、文本向量、混合等方式使用 | 必要时必填 |
| query_image_id | 已上传的查询图片引用 | 仅图片语义查询使用 |
| mode | 检索模式 | hybrid |
| knowledge_base_ids | 要检索的知识库列表 | 至少一个；页面可显式选择“全部知识库” |
| knowledge_ids | 限定文档 | 空表示不进一步限制 |
| filters | 目录、标签、文件类型、入库时间、分块类型；另含 media_types、content_origins、媒体时间范围、音轨与匿名 speaker_id | 不额外限制；媒体时间范围指文件内播放时间，详见第 16 节 |
| top_k | 最终返回数量 | 10，范围 1–100 |
| candidate_k | 每路候选数，不能小于 top_k | 50，最大 500 |
| rerank | auto、enabled、disabled，以及模型覆盖 | auto，有可用模型才执行 |
| include_context | 是否补齐父块或相邻上下文 | true |
| include_sources | 是否携带来源引用 | true |
| explain | 返回各路诊断信息 | false |
| allow_partial | 多路检索允许部分通道失败时返回其余结果 | multi 默认 true，其他模式按明确能力校验 |

同一过滤条件内部多个值按 OR 处理，不同条件之间按 AND 处理。过滤在各路召回和图谱扩展时都必须保持生效，不能在扩展后带入范围外的文档。

预计算查询向量作为高级输入时，必须声明对应模型身份并验证维度。跨知识库检索按向量模型和索引分组，不能直接比较来自不同向量空间的原始相似度。

### 5.3 各方式的专用参数

| 方式 | 专用参数 |
| --- | --- |
| keyword | 检索字段、中文分词策略、短语匹配 |
| vector | 模型覆盖、该索引适用的相似度阈值 |
| hybrid | 融合方式、两路权重、RRF 平滑常数 |
| graph | 实体候选、关系类型、最大跳数、节点和证据上限 |
| wiki | 页面类型、目录、全文或页面混合检索策略 |
| image_text | OCR/描述/属性检索字段、属性过滤 |
| image_vector | 查询类型 text/image、多模态模型、相似度阈值 |
| multi | 启用通道、各通道候选数和融合权重 |

默认采用按排名融合的 RRF，平滑常数 60。混合检索的向量权重为 0.7，关键词权重为 0.3；这些是可调整起点，不是普适最佳参数。

多路检索避免同时选择 hybrid 与其内部的 keyword/vector 通道，防止重复计权。图谱默认一跳，最大两跳；对节点数和证据量设置明确上限。

不设置跨所有模型通用的固定分数阈值。PostgreSQL 全文排名、向量相似度、RRF 和重排分数分别保留名称与含义，阈值按各自模型或引擎配置。

### 5.4 统一结果结构

| 字段 | 内容 |
| --- | --- |
| result_id / result_type | 结果标识；chunk、wiki_page、image、graph_evidence、media_segment 或 video_frame |
| knowledge_base_id | 所属知识库 |
| knowledge_id / chunk_id | 原文档和分块身份，适用时提供 |
| title / content / matched_content | 标题、返回内容、真正命中的内容 |
| channels | 命中的检索通道列表 |
| scores | 各路原始分、融合分、重排分及其分数类型 |
| source_refs | 源文件和原文位置引用，可有多个 |
| images | 图片标识、可访问地址和描述，适用时提供 |
| graph_evidence | 关联实体、关系及其证据，适用时提供 |
| wiki_page | Wiki 页面入口、段落锚点和修订版本，适用时提供 |
| chunk_type / content_origin | 区分正文、OCR、图片描述、ASR 转写、原字幕、视频帧 OCR/描述；模型描述和修订文字均保留来源类型 |
| media | 音视频类型、时长、segment_id/frame_id、音轨、时间范围或时间点、转写版本及缩略图，适用时提供 |

响应元信息包含 request_id、耗时、实际执行的通道、各路候选数量、重排状态、索引版本和 warnings。

存在候选、图谱、证据或内容长度上限时，返回 truncated、truncation_reasons 和实际使用的上限，不伪造完整总数。图谱字符串匹配不生成向量相似度分数；排序依据单独说明。

明确请求某个检索方式，但必要模型或索引不可用时，返回可识别错误，不能默默换成另一种方式。multi 允许部分返回时必须标明失败通道；全部通道失败返回失败，不能伪装成“没有搜到”。

统一检索请求的协议示例：

```json
{
  "query_text": "谁负责知识管理项目？",
  "knowledge_base_ids": ["kb_demo"],
  "mode": "hybrid",
  "top_k": 10,
  "candidate_k": 50,
  "rerank": {"mode": "auto"},
  "include_context": true,
  "include_sources": true,
  "explain": false
}
```

### 5.5 图谱结构与图谱召回的衔接

上游已新增独立结构化图谱查询：按实体名称进行区分大小写的子串匹配，读取一跳邻居，返回有方向的关系、有效来源分块及截断信息；查询本身不调用大模型。

NebulaeKno 的 `/knowledge-bases/:kb_id/graph/query` 统一承接概览、名称查询和邻居展开，复用上游查询能力及旧项目图谱浏览。结构结果包含 entities、relationships、evidence 和 meta。默认上限为 50 个节点、100 条关系、20 条证据；硬上限建议分别为 100、200、50，超限明确返回截断原因。

`/search` 的 graph 模式将图谱证据转换为统一召回结果，并补齐 source_refs。现有上游结构接口不等于自然语言 GraphRAG：实体别名解析、可配置两跳、关系过滤和跨知识库融合都属于 NebulaeKno 适配/新增工作。关系方向与来源文档范围必须保留，同名实体不自动当作同一事实合并。

### 5.6 图片、Wiki 与重排的能力边界

图片语义检索需分别测试文本输入、图片输入及同空间编码，不能仅检查模型名称。上游现有图片向量路径排除扫描 PDF 的整页图像；首版保持此规则，扫描页主要走 OCR 文本检索。若后续增加整页图像检索，应单独建立索引策略和容量预算。

跨知识库 Wiki 检索可复用已有页面检索基础，但统一过滤、页面修订号和原文件引用仍需适配。图片语义重排只有在重排模型确实支持图片输入时启用；否则使用明确标注的文字重排或不重排。

重排接入兼容已验证供应商协议及部分自部署运行时的裸数组响应。必须校验结果索引、数量、有限数值和重复项，保留代码块等原始片段；不能为兼容协议而接受错误排序数据。

### 5.7 音视频检索

保留八种检索模式，音频/视频作为内容类型筛选。关键词、向量和混合检索覆盖转写、字幕及被纳入正文索引的画面文字；image_text/image_vector 覆盖视频代表帧；Wiki 与图谱证据继承媒体时间来源。multi 可以融合这些结果，同时按证据 ID 去重，避免同一画面 OCR 在正文和图片通道中重复计权。

默认支持“用文字搜音视频内容”和“用文字/图片搜视频画面”。首版不额外承诺原始声音相似度检索或任意连续动作识别；它们需要不同模型与索引。视频采样范围、缺失阶段和时间映射精度随结果返回，详见第 16 节。

## 6. 源文件与原文位置定位

### 6.1 必须满足的行为

召回结果应能定位到源文件，并尽可能精确定位到原文页、区域或结构位置。定位信息来自解析与索引时保存的映射，不能由生成模型猜测页码。

点击来源的过程为：结果中的 source_ref → 解析为文件版本与 locator → 打开对应预览 → 跳转位置 → 高亮证据。其他项目可直接使用预览链接，也可读取标准位置数据并自行渲染。

### 6.2 各文件类型的位置协议

| 文件类型 | 可返回的位置 | 页面行为 |
| --- | --- | --- |
| PDF | 页码、页面归一化区域 bbox；可有多页、多区域 | 打开对应版本 PDF，跳页并高亮 |
| 扫描 PDF | 页码、OCR 区域或页面图像 | 跳到扫描页；只有模型实际提供区域时才区域高亮 |
| Word | 标题路径、段落标识、段落内字符范围；可选稳定预览版页码 | 原生按段落定位；有受控转换映射时提供 PDF 页定位 |
| PPT/PPTX | 幻灯片序号、文本框或对象标识、区域 | 打开对应幻灯片并高亮对象或区域 |
| Excel | 工作表名、单元格或范围，如 Sheet1!B12:E18 | 切换工作表，滚动并高亮单元格 |
| CSV | 行列范围 | 跳到相应记录和列 |
| TXT/Markdown | 标题锚点、行号、字符区间 | 滚动并高亮文本 |
| HTML/网页 | 保存的内容版本、标题/段落锚点、字符范围；必要时 DOM 锚点 | 优先定位入库时的内容快照 |
| 图片 | 图片身份、像素尺寸、归一化区域或文字块 | 打开图片并标注区域 |
| OFD | 首先保留原文件与提取文本；页码/区域需补齐解析映射后返回 | 未验证固定版式预览前，展示提取内容和原文件下载，不冒充原版式定位 |
| EPUB | 章节顺序、章节标识、引文和段落 | 打开对应章节并定位；按解析器实际能力提供 |
| 音频 | 音轨、转写/字幕片段、源时间线上的 start_ms/end_ms；词级时间仅在实际可用时返回 | 首版正式入库，点击文字跳转并播放对应时间段，保持字幕同步 |
| 视频 | 语音/字幕时间段；画面证据的 timestamp_ms、frame_id 与可用 bbox；保留原时间戳映射 | 首版正式入库，语音命中播放片段，画面命中定位到对应帧时间并显示证据图 |

Word 原文件的分页可能随字体、软件和布局变化。只有在指定渲染版本中验证过映射，才能把页码作为确定位置返回。OCR 仅返回整页文字时，可以提供页级定位，不能伪造文字框。

### 6.3 标准来源字段

| 字段 | 含义 |
| --- | --- |
| source_ref_id | 可复用的来源引用身份 |
| knowledge_base_id / knowledge_id | 所属知识库和源文档 |
| file_version_id / file_hash | 文件版本与内容校验标识 |
| file_name / file_type | 文件名称和格式 |
| chunk_ids | 支持该引用的原始分块 |
| locators | 一个或多个类型化位置对象 |
| quote | 对应证据原文，受长度限制 |
| precision | region、page、paragraph、range、time_segment、time_word、frame、document 等实际定位精度；帧内区域另由 bbox 表达 |
| file_url / preview_url | 原文件下载地址与带定位参数的查看器页面地址；preview_url 对应预览 manifest 的 viewer_url |
| status | available、stale、missing 或 unsupported |
| mapping / partial | 映射方式与是否只有部分内容具有原文映射 |
| derived_asset_id / transform_id | 如使用矫正图、渲染预览等派生资源，关联原图和坐标变换记录 |

locator 根据格式携带 page、slide、sheet、cell_range、paragraph_id、heading_path、line_start/line_end、char_start/char_end、bbox 等字段，不要求每种格式都具备所有字段。

约定页码、幻灯片、行列编号从 1 开始；字符区间采用 Unicode 码点索引，起点包含、终点不包含，不使用字节或 UTF-16 单元计数。bbox 顺序为 [x0, y0, x1, y1]，使用左上为原点的 0–1 归一化坐标，并声明对应页面或图片版本。多个区域以数组表达。

### 6.4 解析、分块和索引必须保留的映射

解析输出同时包含正文和 source_blocks：每个原始文本区间对应一个或多个源位置。分块时按区间交集计算 chunk 的 source_locators。

归一化、去页眉页脚、表格转换和 OCR 文本插入如果改变正文偏移，必须同步维护映射。为检索补充的标题面包屑不计入原文偏移。

父子块保留各自位置。上下文扩展、去重和合并后，返回独立的命中引用与上下文引用，不能只保留合并后第一个分块的位置。

文件替换、重新解析和索引重建都形成版本关联。旧召回结果仍指向原版本，不能把旧页码套到新文件。旧版本被清理后，来源明确标记为 missing 或 stale。

### 6.5 Wiki、图谱和图片结果的追溯

- Wiki：保留页面自身的修订与段落位置，同时保留支持其内容的原文引用。人工创建且没有文档来源的页面只定位 Wiki 自身，不编造源文件。
- 图谱：实体与关系分别保留证据分块。召回关系时返回证据文件和位置，不用整个知识库代替具体证据。
- 图片：保留图片身份与其在文档中的原始位置。OCR 命中可以定位图片和所在页；文字框仅在解析器确实提供时返回。
- 多路综合：融合时合并来源集合并保留各条证据身份，不能因排序、去重或重排而丢失可追溯信息。

### 6.6 定位接口

定位接口返回标准位置、可用精度、预览入口和原文件入口。服务解析 source_ref_id，调用方不需要知道磁盘路径或内部对象存储位置。

预览默认使用相对 API/页面路径，反向代理部署时由配置的公开地址生成完整链接。所有链接遵循同一公共访问方式。

### 6.8 文本匹配、坐标变换与定位质量

复用上游 Unicode 等价匹配与单次扫描定位索引的改进。匹配时可对规范等价字符进行归一化，但保存原字符串及归一化字符到原始字符位置的映射；不能直接把归一化后的偏移当作源文件偏移。重复段落必须结合页码、结构和上下文消歧。

图片预处理会缩放、旋转、裁剪和做透视变换。必须记录原图与派生图尺寸、完整变换及逆变换；如 OCR 返回框，将框逆变换回原图，必要时返回 polygon 而非错误矩形。再与扫描页或嵌入图在原文档中的位置组合。无可验证变换时仅提供图级/页级定位。

本次查到的上游 PreprocessImage RPC 只返回处理后图片、回退标记和角度/质量等诊断，尚不提供完整坐标变换契约。因此坐标变换持久化、派生图预览与框坐标回映是明确的新增工作，不能声称启用预处理后天然具备精确高亮。

定位服务区分 exact_mapping、verified_text_match、coarse、unavailable 等映射方法；每项同时返回实际 precision、partial 和无法精确定位的原因。PDF.js 解码依赖随管理页面打包，常用预览不依赖运行时从第三方 CDN 拉取资源。

### 7.8 通用接口规则

同步成功返回 200/201；异步受理返回 202 及 task_id、状态地址和结果地址。列表使用 page/page_size，任务事件使用事件游标。

响应统一包含 success、data、meta 或 error。error 包含稳定错误码、中文说明、具体阶段和可重试标记。典型错误包括 INVALID_ARGUMENT、MODEL_NOT_CONFIGURED、INDEX_NOT_READY、LOCATOR_UNAVAILABLE、TASK_CANCELLED、UPSTREAM_UNAVAILABLE。

删除知识库、重建索引等操作在管理页面展示作用范围和确认；公共 API 保持无需鉴权。接口文档不声明调用方的认证方案。

能力接口区分 supported、configured、ready 及 reason。全局支持某引擎不代表指定知识库已建好该索引。固定路径如 `/tasks/stats`、`/sources/resolve-batch` 必须优先于参数路径处理。

试解析等临时产物默认保留 24 小时；引用正式文档的资源按版本策略保留。异步接口返回的任务记录先持久化，再返回 202；任务重试不新建重复业务对象。

### 8.3 中文通用图谱模板

模板标识：`general-zh-CN`。它按现有抽取结构保存 enabled、text、tags、nodes、relations、custom_instructions。

**抽取要求：** 面向通用中文文档，识别人物、组织、地点、产品、项目、技术、概念、事件和流程。实体名称沿用原文；属性和关系描述使用简体中文。只抽取有原文依据的事实；明确别名可合并，含糊指代和缺乏依据的联系不强行推断。保留支持实体与关系的原始分块及位置。示例只用于指导抽取，不作为事实入库。

**关系标签：** 属于、包含、负责、提供、使用、依赖、位于、参与、别名、关联。“关联”只用于原文明确存在但不适合其他标签的关系。

**虚构示例文本：** 张明负责示例公司的知识管理项目。该项目使用示例知识平台，平台依赖文档解析技术。示例公司位于示例市。

| 示例节点 | 示例属性 |
| --- | --- |
| 张明 | 类型：人物 |
| 示例公司 | 类型：组织 |
| 知识管理项目 | 类型：项目 |

### 8.4 中文 Wiki 默认规则

使用简体中文，优先解释核心概念、关键事实、操作流程和关系；按概览、要点、细节、关联页面和来源组织内容。保留原有专有名词，不虚构原文没有的事实。

同一主题跨文档合并，保留多来源引用。出现相互冲突的事实时展示来源与差异，不能直接当作同一事实覆盖。

提取粒度为 standard。并发建议从低值开始，避免多个批次叠加后超过模型服务的并发能力。

### 8.5 图片配置与解析保真规则

流水线采用当前主线已合入的标识 default、smartocr。参数由注册表声明，值按流水线槽位保存，如 `smartocr.preprocess.mode`、`smartocr.ocr_on_unobserved`、`smartocr.ocr.thinking`。使用最终代码里的 off/auto/always，不采用提交过程中过时的 force、preprocess_mode 等命名。

历史流水线标识 ob_cap_ocr、caption_ocr 可在迁移时分别映射到 smartocr、default。未知的新配置应报错，不能悄悄变成另一种处理方式。

配置优先级：显式本次覆盖 > 文档持久覆盖 > 知识库配置 > 已解析出的默认值。未提供字段表示继承，显式 false/off 必须覆盖 true/auto；空字符串不自动代表清除。每次任务保存最终配置和配置版本。全局修改不会改变在途任务。

上游页面预处理默认关闭，本方案保持这一默认值。auto 按观察结果判断是否尝试；always 仍受可读图片、预算和实际能力限制。失败或不适合矫正时保留原图 OCR，记录实际使用的是原图还是派生图。

HTML 正文提取和 Excel 百分比的上游兼容开关默认关闭。本方案面向新知识库，建议启用；此为 NebulaeKno 的产品默认选择。需要把相关选项接入知识库和任务配置，不只依赖 Python 进程级环境变量。切换引擎时检查该引擎是否支持这些选项，不能显示已启用却静默忽略。

Excel 保留显示值、原始值、数字格式和单元格位置是目标契约；上游百分比转文本补丁只提供部分基础能力，完整双值保留需要新增。HTML 不能为去导航而删除主要表格；CSV 保留带换行单元格的记录边界；JSON 保留大整数及原始字符；所有正文重写同步更新 source_blocks。

## 9. 单应用容器、固定中间件与自动初始化

### 9.1 固定组件清单

部署形态确定为：一个 NebulaeKno 应用容器，连接用户已经部署的 PostgreSQL、Neo4j、Redis 三项服务，并挂载一个应用文件卷。应用镜像包含 API、React 静态页面、解析工作进程及文件转换工具；数据库进程运行在应用容器外。

| 固定组件 | 用途 | 部署要求 |
| --- | --- | --- |
| PostgreSQL 17 + pgvector 0.8.x | 业务数据、配置、文件/解析版本、目录、来源、Wiki、任务记录、全文与向量索引 | PostgreSQL 服务端已安装 pgvector；首次启动可由应用在目标库启用 vector 扩展 |
| Neo4j Community 5.26 LTS + 匹配的 APOC Core | 实体关系、图谱索引和图查询 | 使用实例默认 `neo4j` 库；具备业务读写、索引/约束创建及实际使用的 APOC 调用权限 |
| Redis 7.4，单机模式，数据库 0 | 异步队列、任务调度和短期运行数据 | 开启 AOF，使用 noeviction；允许队列实际需要的命令及脚本，应用以独立 key 前缀隔离 |
| 应用本地文件卷 | 原文件、预览副本、图片/媒体产物、临时文件与配置密钥 | 挂载 `/data`，目录可读写且空间满足预算 |

这是唯一实施组合；不提供数据库驱动选择、另一种向量数据库、另一种图数据库、Redis Cluster/Sentinel 或本地数据库回退。各组件具体补丁版本、驱动兼容性与镜像摘要在构建发布前共同锁定验证，不默认使用浮动 latest。

PostgreSQL 保存持久化业务任务、阶段检查点和 outbox；Redis 承载派发与执行队列，不能成为任务事实的唯一来源。图谱抽取结果和来源关联同时保留可重放记录，用于 Neo4j 恢复与核对。文本和图片向量共用 pgvector，按模型及向量空间隔离。

默认 PostgreSQL 业务库名为 nebulaekno，库内应用 schema 固定为 nebulaekno；数据库名可在连接 URL 中指定，但不允许将 postgres、template0、template1 等维护/模板库作为应用目标。Neo4j 库名固定 neo4j，Redis 数据库固定 0，应用 key 前缀由 `nebulaekno:<installation_id>:` 自动生成，无需额外配置。

文件存储固定为本地卷，本版不再添加对象存储类型选择。文件元数据在 PostgreSQL，文件字节在 `/data`；三个中间件连接 URL 之外，标准启动配置已提供卷挂载与默认参数。

### 9.3 三个连接 URL

用户按固定组件要求准备服务后，只需填写以下三个连接 URL；用户名、密码、主机、端口及适用的数据库信息都包含在 URL 中。下列内容是设计示例，不是已写入环境的真实配置。

| 环境变量 | 示例与语义 |
| --- | --- |
| NEBULAEKNO_DATABASE_URL | `postgresql://nebulaekno:ENCODED_PASSWORD@postgres-host:5432/nebulaekno`；路径为待使用/自动创建的业务库名，省略时默认 nebulaekno |
| NEBULAEKNO_NEO4J_URL | `neo4j://neo4j:ENCODED_PASSWORD@graph-host:7687`；固定连接默认 neo4j 库，应用解析凭证后分别传入官方驱动 |
| NEBULAEKNO_REDIS_URL | `redis://default:ENCODED_PASSWORD@redis-host:6379/0`；固定数据库 0，省略路径时取 0 |

Neo4j 的含凭证 URL 是 NebulaeKno 的统一输入约定：启动解析器提取 userinfo 作为认证参数，将不含凭证的地址交给驱动，不能假定驱动直接接受完整 DSN。PostgreSQL 的连接参数以及 Neo4j/Redis 对应的 TLS scheme 按已验证驱动规范解析；证书错误必须报错，不能静默降级连接方式。

密码中的 `@`、`:`、`/`、`?`、`#` 等字符按 URI 规则编码；不再要求重复填写 HOST、PORT、USER、PASSWORD。解析、连接与日志输出统一脱敏，环境 URL 不写入浏览器响应、诊断下载或明文配置记录。

PostgreSQL 首次自动建库使用同一个 URL 账户连接该服务器的 `postgres` 维护库，再创建 URL 指定目标库；账户需具备 CONNECT 和 CREATEDB，以及启用扩展、创建目标 schema/表/索引所需权限。服务端插件文件必须已经存在：应用可以启用 vector 扩展，不能通过 SQL 安装远程主机的扩展二进制。[PostgreSQL 建库权限](https://www.postgresql.org/docs/17/sql-createdatabase.html)、[扩展安装条件](https://www.postgresql.org/docs/17/sql-createextension.html)

Neo4j 服务需预装匹配的 APOC Core 并允许实际使用的过程。插件安装属于 Neo4j 实例准备，应用通过 URL 检查能力，不远程安装 JAR 或修改该实例配置。[APOC 安装说明](https://neo4j.com/docs/apoc/current/installation/)

### 9.4 首次启动自动执行的操作

| 阶段 | 自动行为 | 成功标准 |
| --- | --- | --- |
| 配置校验 | 检查三个 URL、固定协议/版本、参数、文件卷、密钥与资源配置 | 必填项完整，格式有效，无冲突配置 |
| 依赖预检 | 验证地址解析、连接、认证、服务版本及关键权限/插件 | 不以端口可达或 PING 成功代替完整能力检查 |
| PostgreSQL 建库 | 目标库存在则校验；确认不存在时连接维护库自动创建 | 目标库可连接，编码/权限满足应用要求 |
| PostgreSQL 初始化 | 启用 vector，建立固定 schema、表、约束、全文/业务索引及版本记录 | 迁移校验和、DDL 和必需索引状态通过 |
| Neo4j 初始化 | 使用固定 neo4j 库，建立应用安装标记、约束和检索索引 | 约束匹配、必需索引 ONLINE、APOC 实际能力通过 |
| Redis 初始化 | 使用数据库 0，建立安装专属前缀、队列及运行结构 | 真实队列读写/脚本操作和清理探针成功 |
| 默认数据 | 初始化固定公共空间、系统设置、中文图谱模板、Wiki 默认规则 | 幂等插入；不创建用户账号、不替用户创建业务知识库 |
| 本地运行依赖 | 启动解析服务，检查核心转换/媒体能力和资源可用性 | 必需工作进程就绪 |
| 最终检查 | 核对三个组件的安装身份、迁移版本与最低读写能力 | 全部成功后标记初始化完成，开放业务路由并启动任务消费 |

PostgreSQL 首次建立的表覆盖：知识库、文档/文件版本、解析与目录、分块/来源、图片与媒体、Wiki/修订、图谱抽取记录、模型与配置、上传会话、任务/事件/outbox、初始化状态及 schema_migrations。文本/图片向量基础表与元数据结构也在首次启动创建；依赖具体模型维度的向量分区/检索索引在模型绑定后自动创建，不能在模型尚未配置时猜维度。

pgvector 的启用在每个目标数据库内进行；应用验证已安装扩展的版本和实际向量读写能力，再使用模型对应的索引。[pgvector 官方说明](https://github.com/pgvector/pgvector#Getting-Started)

固定 Neo4j Community 使用实例已有的默认 neo4j 库，只在库内创建本应用结构。Community 只支持一个标准数据库，因此本方案不执行任意新图数据库的 CREATE DATABASE；“首次自动建库”适用于 PostgreSQL 业务库，图数据库执行库内初始化。Redis 也没有建表流程，只初始化数据库 0 下的应用 key 空间。[Neo4j 数据库说明](https://neo4j.com/docs/operations-manual/current/database-administration/)、[Redis 数据库选择](https://redis.io/docs/latest/commands/select/)

Neo4j 初始化检查实际使用的 apoc.merge.node、apoc.merge.relationship、apoc.coll.union、apoc.periodic.iterate 等能力，以及创建/更新/删除证据的最小闭环。图谱应用标记和数据均带安装/公共空间/知识库范围；检测到同名结构不匹配或目标库属于另一安装时停止，不覆盖原数据。

Redis 检查 AOF 与 noeviction，以及队列适配器所需命令和脚本权限；需要的诊断读取权限列入固定服务准备要求，不执行 CONFIG SET 修改外部服务。使用短期、带唯一标识的应用探针执行实际操作后清理；不能执行 FLUSHDB/FLUSHALL。AOF 与 key 淘汰策略在 Redis 部署端配置。[Redis 持久化](https://redis.io/docs/latest/management/persistence/)、[淘汰策略](https://redis.io/docs/latest/reference/eviction/)

### 9.5 初始化、迁移与重启的一致性

1. 不使用容器里的“已初始化”空文件作为依据。PostgreSQL 保存 installation_id、schema 版本、迁移校验和、各组件阶段检查点及完成标记；Neo4j/Redis 记录对应身份或命名空间。
2. 连接失败要区分不存在数据库、认证失败、网络错误与权限不足。只有确认目标库不存在时才进入建库分支；已有数据不因连接异常而被当作空环境重新初始化。
3. 建库阶段在同一维护库中取得按目标库名生成的会话级初始化锁；建库成功后连接目标库，取得专用迁移锁并重新检查版本。持锁使用固定连接，避免连接池切换导致锁失效。并发启动者等待有界时间，再读取已完成结果。
4. PostgreSQL CREATE DATABASE 不能放在事务中，单独执行并核对创建结果；可事务执行的表结构迁移逐版本提交，非事务步骤单独记录并提供中断恢复策略。[PostgreSQL CREATE DATABASE 约束](https://www.postgresql.org/docs/17/sql-createdatabase.html)
5. PostgreSQL、Neo4j、Redis 不存在跨组件全局事务。某阶段失败时记录失败并退出，保留已完成的合法步骤；下次检查后续做，不能为“回滚”而删除刚建的整个数据库或其他业务对象。
6. 所有结构创建采用幂等判断，并比对已有定义。IF NOT EXISTS 不是兼容性校验；同名不同结构、未知迁移校验和、未完成的危险迁移或数据库版本高于当前程序时拒绝启动。
7. 再次启动只验证已有状态、补做尚未完成的初始化和执行待应用迁移；不重置模型、默认配置、知识库、Wiki 或图谱。新增系统默认项只补缺失值，不覆盖用户修改。
8. 后续版本启动时自动应用随镜像提供的迁移，破坏性删库/删表/清空数据不进入默认启动迁移；需要人工恢复的失败清楚报出，不擅自删除数据后重试。

首次启动自动创建 `/data` 子目录及配置加密密钥并持久化。已有模型凭证存在而密钥丢失或不匹配时应失败，不能生成新密钥冒充恢复成功。数据库与文件卷记录关联身份，避免把一套数据库与另一套文件误接。

### 9.6 严格启动、健康与失败行为

启动阶段依次为 validating_config → checking_dependencies → initializing_database → migrating_schema → initializing_graph → initializing_queue → checking_runtime → ready。任一步失败进入 failed 并非零退出；不提供“忽略错误继续”或切换到其他数据库的启动参数。

| 情况 | 行为 |
| --- | --- |
| 缺 URL、格式错误、固定数据库/协议不匹配 | 立即失败，指出变量名，不输出包含密码的原始值 |
| DNS/连接超时、服务暂未启动 | 在连接重试窗口内有界重试；超过窗口非零退出 |
| 认证失败、权限不足、插件缺失、结构冲突 | 立即失败，给出组件、阶段、稳定错误码和所缺能力 |
| 初始化/迁移执行失败 | 不开放业务；保存可用检查点、脱敏日志及迁移版本，非零退出 |
| 初始化仍在执行 | `/health/live` 可报告进程存活；`/health/ready` 返回 503；其他路由返回 503，不显示可正常操作的后台 |
| 全部基础设施与核心运行依赖正常 | `/health/ready` 返回 200，开放 React 页面、API、接口文档并启动工作队列 |
| 中间件正常，模型尚未绑定 | 可以进入设置；对应业务阶段 waiting_configuration，不能据此把数据库错误也降级处理 |

日志包含组件、阶段、重试次数、迁移编号和可操作原因；稳定错误码包括 CONFIG_MISSING、INVALID_CONNECTION_URL、DEPENDENCY_UNREACHABLE、AUTH_FAILED、DATABASE_CREATE_DENIED、EXTENSION_UNAVAILABLE、GRAPH_PROCEDURE_UNAVAILABLE、REDIS_CAPABILITY_MISSING、MIGRATION_FAILED、SCHEMA_VERSION_TOO_NEW。没有数据库连接时也必须能通过标准输出读取失败原因。

进程存活不等于服务就绪，容器健康检查使用 ready，并为合法迁移保留启动宽限期。正常运行后持续检查三项必需中间件：失联时撤销 ready、暂停新任务与业务读写；短暂恢复后重新检查再开放，持续失败超过预算则有序退出，由部署端按重启策略处理。不得缓存一个永远成功的 ready 状态。

关闭时先停止接收任务和写请求，再取消/等待受控工作进程、写入阶段检查点并关闭连接；外部数据库、Neo4j 和 Redis 不由应用关闭。可选格式能力未安装按能力矩阵标记，但必需中间件不可选，核心解析进程启动失败也不能报告 ready。

### 9.9 镜像、资源与交付

多阶段构建包括 React/Vite、Go、Python 和媒体/文档转换依赖，最终生成 `nebulaekno:<版本>`。运行镜像不携带 PostgreSQL、Neo4j、Redis 服务端或数据库数据目录，也不需要额外 Node 页面服务；SPA 静态资源、API 与预览共用 Go HTTP 服务。

交付独立源码、应用 Dockerfile、只定义一个应用服务的启动配置、三个 URL 的环境模板、固定中间件准备说明、初始化/迁移说明、OpenAPI 和中文使用文档。中间件准备说明给出固定组件、匹配插件、所需账户权限和验证清单；不提供多种数据库方案供选择。

优先验证 Linux amd64。应用容器初始以 4 核 CPU、8GB 内存验证低并发解析和音视频处理，三个外部中间件各自分配资源；这是验证起点，容量以样本和压测为准。预处理 2048MB 上限与其他本地工作进程统一计入应用预算。

启动验收必须覆盖空库自动初始化、权限/插件错误、依赖故障、迁移中断、重复启动、任务恢复及文件定位，不能仅测试首页。不得把插件已安装、数据库账号存在或远程服务已部署伪装成应用能仅凭 URL 自动完成的服务器安装步骤。

### 9.10 备份、恢复与实例范围

完整备份覆盖 PostgreSQL、Neo4j 与文件卷及密钥，统一记录安装身份、schema/图谱版本、文件清单和检查点。应用内备份接口负责文件归档、业务导出和协调清单；外部数据库的原生备份由对应服务的工具或部署端任务完成，连接 URL 不等于有远程数据库主机管理权限。

首版采用维护窗口：暂停新写入与任务消费，等待在途事务及 graph outbox 到达一致检查点，再取得数据库与文件快照。Neo4j Community 的原生备份/导出按其工具要求在服务侧执行；不能把在线文件复制当作一致快照。若使用业务导出恢复图谱，必须包含足够的抽取结果和来源记录，并验证重建后索引/证据一致。

恢复先校验 PostgreSQL、Neo4j、文件卷与加密密钥的配套身份，再运行迁移/能力检查，最后从 PostgreSQL 恢复任务并重建需要的 Redis 数据。旧 Redis 队列不得未经核对直接覆盖恢复后的任务状态。原始文件丢失时即使索引仍在也应如实标记 missing。

首版按单应用实例部署。初始化锁防止并发建库/迁移冲突，不等于已经支持多实例文件存储、任务调度或高可用；不把多个应用实例共享本地文件卷作为当前交付能力。

## 10. 数据与任务设计要点

主要数据对象为：知识库、文档、文件版本、解析版本、文件目录版本/节点、分块、分块版本、图片、派生资源/变换记录、媒体音轨/字幕轨、转写版本/片段、视频帧证据、时间映射、上传会话、来源引用、Wiki 页面/修订/链接、实体/关系/证据、模型、配置版本、配置草稿、任务与任务事件。

文档、分块、图片和 Wiki 都保留所属知识库。图谱证据连接到原始文档版本与分块，不仅保存实体名称。

任务状态包含 queued、running、waiting_configuration、cancelling、succeeded、partially_failed、failed、cancelled。各处理阶段单独记录状态、数量、耗时和错误。

取消任务后，后续阶段不继续调用模型；重试只处理可重试阶段，并防止重复建立分块、Wiki 页面或图谱证据。文件删除与知识库删除需要关联清理文件、索引、图谱和 Wiki 来源。

持久化任务记录包含业务幂等键、阶段检查点、尝试次数、下次执行时间、租约及最后心跳、取消标记、配置快照。工作进程恢复时先判断阶段是否已经产生结果，再重试；采用至少一次执行加幂等写入，不承诺未经实现的“恰好一次”。数据库状态和任务派发使用事务性待执行记录，避免接口已返回 202 但进程退出后任务丢失。

相同图片字节可以复用底层 blob，但每个文档版本、页内出现位置仍有独立 occurrence 和 source_ref。处理结果缓存键至少包含内容 hash、模型/配置版本与处理动作。删除或克隆回滚仅解除本次引用；有其他有效引用时不删除共享 blob。相关唯一约束、引用索引与迁移统一在 PostgreSQL 验证。

## 12. 实施顺序与验收

实施顺序建议为：确定接口与来源协议 → 固定上游/本地功能基线 → 固定中间件连接、初始化与迁移 → 单应用容器严格启动 → 独立后台和公共空间 → 模型与默认设置 → 知识库和上传 → 解析/分块/图片/索引 → Wiki/图谱 → 多路召回和原文定位 → 管理页面完整交互 → 容器与恢复验证。

P0 为先完成的核心链路，P1 为首版内的增强与完整验收，P2 为后续可选能力；P0/P1 均未在新项目实施。

| 阶段 | 范围 |
| --- | --- |
| P0 | 公共 API、模型/默认设置、先建库再上传、解析与分块、每文件目录树、智能图片处理、音视频正式入库/转写/画面索引/时间定位/兼容播放、大文件续传、中文 Wiki/图谱、关键词/向量/混合召回、基本原文定位、单容器和任务恢复 |
| P1 | 八种召回完整适配与对比、图片预处理及来源坐标回映、来源版本与批量解析、配置草稿、OFD 保留与定位分级、多格式预览与转换、完整管理交互和资源一致性验证 |
| P2 | 按需接入外部数据源、MCP、定时维护；聊天助手、多智能体和异步 Shell 另行定义产品范围 |

以下内容作为最终验收标准：

1. 一个应用镜像启动一个应用容器；配置 PostgreSQL、Neo4j、Redis URL 并挂载文件卷后，只有全部初始化成功才打开中文管理页面；公共接口无需登录。
2. 设置模型和解析默认值后，可以先创建知识库，再批量上传文件；Wiki 和知识图谱默认开启并使用中文模板。
3. PDF、Word、Excel、PPT、文本和图片等代表性样本有清晰的解析与处理结果，失败阶段可定位并重试。
4. 八种检索模式能独立配置和测试；不具备能力时返回明确错误或标记多路部分失败，不能假装执行成功。
5. 关键词模式不依赖向量模型；重排缺省时仍能召回；图片文字与图片语义检索的能力区分正确。
6. 检索结果包含文件身份、版本和定位精度；PDF 跳页、表格单元格、幻灯片或文本位置可按样本核对。
7. 上下文扩展、融合和重排后仍保留全部必要来源；Wiki、图谱和图片结果能追溯到有依据的原文位置。
8. 文件更新后旧引用不错误指向新版本；删除后引用状态与索引、图谱、Wiki 的清理符合规则。
9. 容器重启保留模型配置、知识库、文件、Wiki、图谱和索引，并恢复或明确终止未完成任务。
10. 管理页面与第三方调用使用同一接口；接口文档中的请求、错误和返回字段与实际实现一致。
11. 图片预处理的 off/auto/always 符合实际语义；超时、不适用或依赖故障时使用原图并记录原因；原图永不被覆盖。
12. 矫正图的 OCR 框只能在具有可验证逆变换时标回原图；Unicode 组合字符、重复段落和多页引用不会高亮到错误位置。
13. 扫描件 Wiki 使用有效 OCR 正文；空 OCR 不生成无依据内容。图谱结果保留方向和有效证据，截断有明确标记。
14. CSV 多行单元格、Excel 百分比、JSON 大整数、HTML 表格和正文提取均有代表性样本；显示值与源位置可以核对。
15. 相同图片被多文档引用、删除其中一个文档、克隆中途失败等情况下，其他引用仍可打开并定位。
16. 图谱连接正常但 APOC 缺失时启动失败；必需中间件网络可达且公网断开时，本地预览资源仍可用；重启后事件、任务和来源版本符合约定。
17. 每个文件默认触发目录提取并保留独立状态；有效章节的标题、父子关系和源位置可核对，扫描件等待已有 OCR，无目录时不生成虚构章节。
18. 文件目录只返回结构及定位元数据；允许模型辅助提取和校验，但新增/修订标题必须有原文证据，页码与段落由来源映射核对，疑点不伪装为已确认。
19. 重提目录、替换源文件和更换解析版本均形成正确的目录版本关联；旧节点不误跳新文件，同页多章节按可用段落/区域定位，未知位置如实标记。
20. 预览格式按第 15 节矩阵验收；解析支持、浏览器可展示、转换可用、精确定位分别报告，不能只凭文件扩展名宣称完整支持。
21. 目录点击与召回来源在同一文件/预览版本中定位；转换副本不套用原文件未经验证的页码，失败格式仍有原因、可用内容与下载入口。
22. 音频与视频使用普通知识库上传接口正式入库；语音、字幕、画面文字可检索，视频帧能参与已配置的图片检索；每条结果携带对应媒体版本和可用时间来源。
23. 点击音视频命中能跳转并播放对应时间段，视频画面命中能回到帧时间；无声视频、可变帧率、非零起始时间、多音轨、转写分段拼接、转码与原件间的时间映射均列入验收。
24. 大文件上传中断、容器重启、模型缺失、局部识别失败与帧预算耗尽均有明确状态；恢复后不重复生成片段，旧结果不跳到新文件版本。详细准确性与播放验证见第 16 节。

## 14. 每文件自动提取目录结构树

### 14.1 参考实现与功能范围

参考 [PageIndex Flash 原始树提取说明](https://github.com/VectifyAI/PageIndex/blob/cc62cce78483112b83877c2852fb3c0d7f991f54/pageindex/flash/README.md) 与 [接口实现](https://github.com/VectifyAI/PageIndex/blob/cc62cce78483112b83877c2852fb3c0d7f991f54/pageindex/flash/api.py)。核对提交为 `cc62cce78483112b83877c2852fb3c0d7f991f54`，提交时间 2026-10-22 15:08:08（UTC+8）。

参考实现提供排版、书签提取和模型辅助优化等不同路径，原始结构使用 title、node_id、start_index、end_index、nodes。本方案借鉴其目录表达和定位思路，采用准确性优先的混合提取，不要求固定使用 PageIndex，也不限制使用大模型。调用模型的目的为识别真实目录、修复层级和核验位置，不能直接照搬会生成额外摘要或主题节点的完整索引流程。

本次功能产出为：每个文件的目录标题、层级、父子关系、顺序，以及可验证的源位置。原文没有章节结构时如实返回无目录。节点标题保留原文语言，状态与控件使用中文。本次不新增树推理检索、章节摘要或目录问答；现有八种检索继续使用原方案。

### 14.2 提取流程

1. 文件保存版本并进入解析，读取原生大纲、标题样式、结构化正文和 source_blocks；扫描件在已有 OCR 正文可用后继续，困难页面可调用视觉模型复核。
2. 校验原生目录的页码、顺序、重复项和标题正文证据，从标题样式、编号、字体/位置特征、Markdown/HTML 语义及印刷目录形成候选集。代码围栏、重复页眉页脚和普通表格行不直接当作标题。
3. 按准确性策略调用大模型，提供候选集、原文块 ID、真实页/段落标记和必要上下文，识别遗漏标题、纠正错误层级、处理目录与正文冲突。原生目录与正文已经完整一致时，auto 模式可直接使用验证结果；always 模式仍做模型复核。
4. 模型以受约束 JSON 返回原文标题、父子关系、证据块 ID 和所选位置候选，不生成主题摘要。每个新增或修订条目必须能在正文、目录页或页面图像中找到依据。
5. 程序验证 JSON、无环树、节点唯一、真实证据、源位置边界与顺序。逐项对齐原文：标题在目录页出现不等于章节位置已经确认；模型提出的页码只是候选，必须另行验证。
6. 对遗漏、重复、页码偏移、父子范围冲突等疑点，定向读取邻近页面或原图，最多做配置预算内的纠错复核。长文件分窗口处理，窗口有重叠并按原文位置去重，最后对整棵树检查顺序、层级和覆盖。
7. 仍未确认的节点标为待核验，给出原因与原文对照入口；无来源的新标题不进入正式树。保留 source_title 和必要的 display_title，OCR 修正需经过原图证据核对并记录修正依据。
8. 原子保存目录版本，任务完成后刷新文档详情。目录提取失败或超时只影响该阶段，不阻止已完成的文档解析与可检索文本使用。

印刷目录页列出的章节可以成为候选，但页号必须与实际物理页对应。印刷页码与 PDF 物理页码分别记录，不简单假定固定偏移；验证失败时保留标题、标记位置未确认，不跳到目录页本身冒充目标章节。

参考实现可能自动补 Preface、intro 或 Page N 导航节点。NebulaeKno 的“提取目录”只保留有源结构依据的条目；文件名根入口属于界面导航，页列表如需显示也单独呈现，不混为提取出的章节。原生结构缺失时可以使用模型从原文提取真实标题；模型也未发现有依据结构时返回无目录。

### 14.3 各格式处理规则

| 文件类型 | 提取依据 | 范围与降级 |
| --- | --- | --- |
| 文字 PDF | 校验后的内置书签、标题排版、编号、经核对的印刷目录 | 结合结构候选与模型核验；返回物理页号，区域精度受实际映射限制 |
| 扫描/混合 PDF | 已有 OCR 的标题块、编号、版面与页映射，必要时视觉复核 | 复用本系统 OCR，处理错字、页码和版面疑点；信息不足时返回部分结果或待核验状态 |
| DOCX/Word | 标题样式、outline level、目录字段与真实正文标题 | 定位段落或块；旧格式先经现有受控转换，并保留来源版本 |
| Markdown | 语法解析后的标题节点 | 排除代码块中的伪标题，保留行号和字符范围 |
| HTML/网页 | h1–h6 等结构标题 | 使用入库快照与最终正文，保持 DOM/文本位置映射 |
| PPT/PPTX | 文件已有分节、幻灯片标题 | 节 → 幻灯片；无标题页面以“第 N 张”作结构导航标签并标明 title_source=position_label |
| Excel | 工作簿与工作表名称，实际存在的命名表/区域 | 首版至少提取工作表层；不把每个数据行扩成目录节点 |
| TXT | 明确的章节编号、可验证的独立标题行，模型辅助识别隐含排版层级 | 仅提取源文件实际标题，不从普通段落概括主题；无法确认则保留原因 |
| OFD | 已有目录信息或解析器输出的真实标题块 | 当前本地适配需补映射；不能单凭分页伪造章节树 |
| EPUB | 原生导航目录、章节结构与标题 | 关联章节顺序与来源位置 |
| 音频/视频 | 容器已有章节、经核验的字幕/语音章节提示、视频中的真实标题画面 | 保留实际标题与时间；无真实章节时返回空树，时间线和转写段另作导航，不把自动概括主题伪装成提取目录 |
| 图片 | 已有 OCR 中可确认的标题层级，必要时模型读取原图核对 | 单图无结构时返回无目录，视觉复核不得生成原图没有的章节名 |
| CSV/JSON 等 | 适配器有明确结构时提取，如命名对象层级；不逐行逐值展开 | 首版无可靠目录适配则返回空树及原因，文档本身仍正常入库 |

各格式通过既有解析器、结构候选和模型核验适配，PageIndex 仅为可参考的实现之一。所有文件都会有目录处理结果，但并不保证每个文件都存在章节目录。

### 14.4 返回结构

目录响应只包含树和定位元数据，不包含章节正文、摘要、关键词、向量或模型回答。

| 层次 | 字段 | 说明 |
| --- | --- | --- |
| 文档 | knowledge_id、file_name | 文件身份；知识库归属沿用文档接口 |
| 版本 | file_version_id、parse_version_id、outline_version_id | 目录依赖的原文件、解析及目录版本 |
| 状态 | status、reason、task_id | queued、running、waiting_ocr、waiting_media、waiting_configuration、ready、partial、empty、failed、disabled；task_id 适用时返回 |
| 结果 | structure、node_count、truncated、truncation_reasons | 有序根节点数组、实际保存节点总数和完整性信息 |
| 节点 | node_id、title、level、children | 目录版本内唯一 ID、展示标题、归一化层级、有序子节点；叶节点 children=[] |
| 标题溯源 | source_title、display_title、title_correction_reason | source_title 保留原始提取文字；display_title 默认等于 source_title，仅有可核验原文证据时校正 OCR 错字；title 等于 display_title，发生校正时记录依据 |
| 依据 | extraction_source、title_source、original_level | 来自 native_outline、heading、layout、printed_toc、ocr_heading；媒体可为 native_chapter、subtitle_heading、spoken_heading、frame_heading；区分原标题与位置导航标签 |
| 方法 | extraction_method、model_id、verification_rounds | 原生、布局、混合模型或视觉辅助；记录实际使用模型与复核次数 |
| 核验 | verification_status、evidence_refs、review_reasons | verified、needs_review、unresolved；关联原文块/页面证据与疑点；模型自报置信度不能代替证据 |
| 位置 | start_page、end_page、start_locator、end_locator | PDF 页码或类型化原文位置；无法确定的字段为 null 或省略 |
| 引用 | source_ref_id、position_status | 目标章节的来源引用；位置状态为 verified、coarse、unresolved，按实际能力返回 |

复用 PageIndex 结果时，将 nodes 映射为 children，将 PDF 的 start_index/end_index 映射为 start_page/end_page。页码从 1 开始，页范围含首尾；相邻章节可能在同一页，不能要求页范围互斥。有字符级边界时遵循第 6 节的起点包含、终点不包含约定。

目录 ID 绑定 outline_version_id；重新提取不保证原 node_id 跨版本复用。目录节点定位到标题起点，父节点的范围可覆盖整个子树。终点无法验证时留空，不根据标题文字猜页数。

```json
            "children": []
          }
        ]
      }
    ]
  }
}
```

完成预定检测且确无目录时返回 status=empty、structure=[]、node_count=0，并给出 no_detectable_outline 原因。OCR 未完成为 waiting_ocr；所需转写或视频帧未就绪为 waiting_media，并注明依赖阶段；必需的模型尚未配置为 waiting_configuration；模型故障、预算耗尽或关键疑点未解决为 partial/failed，不能当成“没有目录”。等待依赖和排队的时间不计入目录提取本身的执行超时。格式没有目录适配时提供 unsupported_outline_format 原因。已知标题但位置不明时可返回节点，source_ref_id 为空且 position_status=unresolved。

### 14.5 接口与版本更新

统一使用第 7.3 节的两个目录接口。GET 支持 file_version_id、parse_version_id、outline_version_id；省略时读取当前文件/解析版本的最新可用目录，不能返回旧文件目录冒充当前版本。接口处于生成中时返回真实状态及任务，不把空数组解释为已经完成且无目录。

POST rebuild 支持指定已有文件/解析版本和目录提取配置。相同版本与配置的在途请求复用任务；成功后原子切换当前目录指针。失败时保留最后成功版本，并明确标注它是否仍匹配当前文件。

GET 可带 parent_node_id、depth、cursor、limit 获取某棵目录版本中的局部树；分页以同一父节点的有序子节点为单位。默认读取完整树，超出单次响应预算时返回当前响应的 has_more、next_cursor，或各分支的 children_has_more 与可继续加载入口。提取本身的 truncated 与响应分页的 has_more 分开记录。

删除文件时按已有版本保留策略清理目录和引用；目录随 PostgreSQL 一同备份。目录提取的引擎版本、源文件 hash、解析版本、模型身份、提示词版本与有效配置组成可追溯记录；缓存按这些版本关联，不要求模型再次调用产生完全相同的树。

### 14.6 实施与验收补充

本功能纳入首版 P0，后续实现顺序为：冻结目录协议 → 文字 PDF 与 Markdown 候选提取 → 模型校正与证据核验 → DOCX/HTML/PPT/Excel 适配 → 扫描件 OCR/视觉复核 → 目录树页面和原文定位 → 版本/空结果/超限验证。

样本覆盖：带书签 PDF、无书签但有标题 PDF、同页多章节、印刷页码与物理页不一致、扫描目录页、混合 PDF、DOCX 标题跳级、Markdown 代码围栏、无标题文本、多工作表文件、中文与混合语言标题。验收以实际标题、父子关系和源位置为准，不承诺参考项目未给出的准确率。

### 14.7 目录准确性验证

建立人工标注样本，分别评估标题精确率、标题召回率、父子关系正确率、章节顺序和原文跳转命中率。统计每种格式及扫描件质量，单独统计未确认项，不能将其排除后宣称总体准确。

必须检验：模型补出的标题是否真实存在、目录页的页号是否指向正确正文、重复标题能否区分、双栏/页眉是否污染目录、OCR 错字是否由原图验证、跨窗口章节是否遗漏或重复。对始终无法确认的条目展示待核验，不靠多次生成取多数票当作事实。

模型复核默认优先解决有冲突或低质量的部分。存在真实原文依据且结构检查全部通过时才能标 verified；标题证据和位置证据分别判定，已确认标题但目标位置未知可以保留，不能伪造精确跳转。验收报告同时给出正确结果、遗漏、误识别、待核验和资源消耗。

## 15. 多格式文件预览

### 15.1 上游实际能力与接入原则

本次复核基于第 13 节固定的上游 main 提交，检查了 `frontend/src/utils/filePreview.ts`、`frontend/src/components/document-preview.vue`、`pptxPreview.ts`、`epubPreview.ts`、`PdfSourceViewer.vue` 和依赖清单。此次为静态代码核对，未运行各格式样本。

上游已有 PDF、DOCX、PPTX、图片、表格、Markdown、文本/代码、HTML、音频、视频、Mermaid 和 EPUB 预览分支。格式识别、实际渲染、知识入库及定位能力各有边界：旧版 DOC/PPT 未注册为原生预览；知识库上传 HTML 默认显示源码，脚本运行仅用于其另一类生成产物；图片和媒体部分格式还依赖浏览器编解码能力。MHTML、XMind 等能进入解析链路，也不意味着已有专用原版预览器。

### 15.3 页面设计

文档详情沿用“目录侧栏 + 文件主体 + 证据/解析内容”的布局，辅助侧栏可折叠。顶部显示文件名、格式、源文件版本、当前预览方式与定位状态，工具栏按格式提供操作。

| 区域 | 行为 |
| --- | --- |
| 文件预览/解析内容切换 | 原版式或格式渲染与解析正文分开标识；两者尽量同步来源位置 |
| 文件目录 | 使用第 14 节的目录，点击标题定位；待核验节点显示状态，已知标题位置与范围分别处理 |
| PDF/幻灯片导航 | 缩略图、页码/张数、前后页、缩放、适应宽度与全屏 |
| 表格导航 | 工作表列表、行列标识、当前命中单元格、原始值与显示值 |
| 图片 | 原图/派生图切换、缩放、旋转查看与命中区域；旋转显示不能改变保存的源坐标 |
| 音视频 | 播放、进度、音量、倍速、转写跟随、代表帧轨道和时间命中；支持区间播放与原文件时间定位 |
| 预览状态 | 准备中、转换中、可预览、部分展示、失败或不支持；显示可执行的重试和下载 |
| 来源提示 | 明确原文件、浏览器格式渲染、转换副本、解析内容四种来源，不把其中一种静默冒充另一种 |

知识库列表、图片来源、Wiki 引用、图谱证据和召回结果均打开相同的预览入口，并传入 file_version_id、source_ref_id 及适用的 outline_version_id/preview_version_id。切换文档后忽略旧异步结果，切换版本后重新验证定位。

### 15.4 预览接口契约

第 7 节新增 preview/manifest、preview/rebuild、preview-assets 和 file-formats。业务页面读取 manifest 决定渲染方式，不根据扩展名自行假设能力。

| 字段 | 含义 |
| --- | --- |
| knowledge_id、file_version_id、file_hash | 原文件身份与版本 |
| preview_version_id、renderer_version | 预览产物与渲染器版本；转换使用的字体/转换器配置纳入缓存身份 |
| status、reason、task_id | ready、processing、partial、failed、unsupported；转换任务与原因 |
| detected_format、mime_type、preview_kind | 识别出的格式与使用的预览器 |
| representation | original、rendered、converted、parsed_content |
| content_url、asset_urls | 可预览内容流与所需资源的公共服务地址；不返回磁盘路径或客户端临时 blob URL |
| viewer_url、download_url | 带版本和来源定位参数的管理页面地址、原文件下载地址 |
| page_count、sheet_names、duration_ms | 按格式提供已知页数、工作表或时长 |
| locate_capabilities | page、region、paragraph、cell、slide、section、text_range、time 等实际能力 |
| mapping_version、warnings | 对应映射版本、转换限制和已知缺失 |

`GET /knowledge/:knowledge_id/preview` 提供文件内容流，既有 source_ref.preview_url 应指向可执行跳转/高亮的 viewer_url；模型或第三方客户端也可读取标准 locator 自行渲染。带定位参数的查看器链接与纯文件流地址分别表达。

版本参数统一使用 file_version_id；指定转换产物时再传 preview_version_id。省略时读取当前源文件对应的可用产物，不能返回旧源文件的预览冒充当前结果。查看器页面接收 source_ref_id，并解析其 locator 完成定位；版本不一致时返回明确状态。

对于 PDF/媒体，内容流支持适用的 Range 请求和正确 MIME；转换副本使用自己的 ETag/hash。转换任务返回 202，准备完成后通过 manifest 获得可用产物。preview-assets 只解析已登记资源 ID，不接受任意本地路径。

`/file-formats` 分别返回 upload_supported、ingestion_supported、outline_supported、preview_supported、preview_requires_conversion、locate_capabilities 和 reason；需要浏览器解码的能力还应标注 client_dependent。服务器可提供候选格式，客户端完成能力检测后再确定当前可展示方式。

### 15.5 转换、缓存与原文定位

原件始终保留，转换写入独立预览版本。缓存键至少包含源文件 hash、转换器/渲染器版本、字体配置和转换参数；目录、证据和高亮不能跨版本混用。

Word 的原生定位保持段落/块语义，受控 PDF 的页码属于该预览版本；PPT 转换校验幻灯片顺序和数量；Excel 保留工作表与原单元格地址；MHTML/HTML 保留原始字节、清理后 DOM 和文本位置之间的关系。没有可验证映射时降低精度并说明，不把“预览成功”当成“精确定位成功”。

转换前检查容量与格式，转换工作进程设并发、超时和内存预算。读取大文件采用按页、按表、按需资源及虚拟列表策略，避免所有文件都完整下载并一次性渲染。格式识别结合扩展名、MIME 和必要的文件头；AVIF/HEIC 等图像容器不应误判为音频/视频。

静态 HTML、SVG、EPUB 等展示内容经清理；页面不执行上传文件的脚本。文内图片与附件由服务返回版本化资源地址，适配本方案公共访问方式。PDF.js 的 worker、CMap、字体与 WASM 等实际需要的资源随镜像本地提供。

### 15.6 验收与当前状态

验收样本覆盖：文字/扫描 PDF、中文字体 DOCX、DOC/PPT 转换、多工作表与合并单元格、CSV 多行字段、含图片与公式的 Markdown、跨章节 EPUB、静态 HTML/MHTML、复杂图片与多页 TIFF、可播放及不可解码媒体、Mermaid、XMind 结构化内容和 OFD 渲染。

重点验证：目录与召回引用打开同一版本；页/段落/单元格/时间跳转正确；浏览器不支持的编码返回明确原因；转换不覆盖原件；PPTX 少页和 EPUB 缺章不被误报完整；页面退出后释放资源；断网时已打包的预览组件和本地文件仍可用。

本轮仅更新方案。未安装新的运行依赖、未执行格式转换或目录模型调用、未编写程序代码。

## 16. 音视频入库、检索与时间定位

### 16.1 正式入库范围

音频和视频均属于知识库中的正式知识文档，默认 ingest_mode=indexable，纳入首版 P0。保存原文件，产生可检索内容、带时间来源的分块、处理状态与版本；继续使用现有 Wiki、知识图谱和八种召回方式。文件上传成功、内容解析成功、索引就绪与可播放分别记录。

| 类型 | 目标格式 | 入库内容与定位 |
| --- | --- | --- |
| 音频 | MP3、WAV、M4A、FLAC、OGG、AAC、Opus 等 | 音轨元数据、带时间转写或已验证字幕、分块、可用章节；结果回到源音频时间段 |
| 视频 | MP4、MOV、WebM、M4V、OGV、MKV、AVI 等 | 音轨转写、字幕、代表帧 OCR/描述、缩略图、分块与章节；结果回到原视频语句或帧时间 |
| 配套字幕 | SRT、WebVTT，及适配器能正确读取的内嵌字幕轨 | 绑定已有媒体文档与文件版本，保留语言、来源、时间及人工偏移校准记录 |

扩展名只表示候选容器格式，实际支持由封装、编码、轨道和镜像构建共同决定。首版验收至少覆盖常见音频、H.264/AAC 的 MP4/MOV、VP9/Opus 的 WebM，以及可由内置解码器转换的 MKV/AVI 样本。未知或无法解码的编码返回明确原因；同一格式的一个样本通过不代表所有编码组合都通过。

模型缺失时可以先保存文件，相关阶段等待配置；已完成的独立阶段可以继续使用。无声视频仍执行画面处理；纯音乐或无可辨语音的音频允许没有转写，但不生成虚假语句。播放失败与解析失败分别报告。

### 16.2 处理流水线

1. 上传并校验完整性，建立知识库文档与源文件版本；大文件支持分片续传，不把整个文件读入内存。
2. 使用 ffprobe 读取格式、时长、音视频/字幕轨、章节、起始时间与时间基准；记录真实音轨选择、旋转信息和可解码性。
3. 读取可用字幕与章节，校验范围、顺序、语言及音画同步。默认 auto：已核验且适合检索的字幕可以作为转录正文，否则对选定音轨执行 ASR；可显式要求两者都保留。翻译字幕与原语言转写分别标注。
4. 音频按语音边界和服务限制拆成带少量重叠的处理片段，记录各片段在原音轨及源文件时间线上的位置。视频先提取选定音轨，不能丢掉它相对于视频的起始偏移。
5. 调用 ASR 得到语句文字和时间；支持词级时间时一并保存。对重叠区域结合时间与文字去重，保留真实重复说话；按时间排序合并结果，不把多个分段各自的 00:00 当作整个文件的起点。
6. 视频并行执行场景变化检测与定时代表帧采样、相似帧去重、OCR 和画面描述。每帧保留解码时间戳、原视频版本、坐标变换和处理状态；视觉向量仅在相应模型启用时生成。
7. 按语句边界、时间上限与文字长度形成检索分块；将字幕、ASR、画面 OCR 和模型描述分别标注。文字索引与画面索引各自记录覆盖范围，引用不得在合并时丢失。
8. 提取有原文依据的媒体章节目录，生成 Wiki/图谱并继承时间引用；按需要生成兼容播放副本和时间映射，发布版本化结果。

ffprobe 可以读取媒体流、帧和章节信息；本方案在其输出基础上建立统一来源与版本记录。[FFprobe 官方文档](https://www.ffmpeg.org/ffprobe.html)

视频代表帧属于采样证据。记录采样策略、已处理时间窗、帧数、最大间隔、失败窗口和预算截断信息；不能据此宣称完整识别了每一帧或所有连续动作。画面识别仅确认采样时刻，除非额外验证了持续范围，否则不扩大成整段时间的事实。

### 16.3 转写、分块与目录准确性

ASR 保留原语言和实际返回的文字，原始结果与校订结果分开存储。数字、人名、时间及专有名词不能仅凭大模型猜测补齐；低质量区间显示疑点并允许重处理。可选匿名 speaker_id 仅表示该转写版本内的说话人分组，不跨文件推断真实身份。

分块沿用默认 512 字符作为目标，以完整语句为边界，并增加默认 60 秒的时间跨度目标。重叠最多一条语句且建议不超过 10 秒；模型仅提供长句时间时，保留该句真实区间并标记超长，不能平均分配文字来伪造词级时间。检索块保存 segment_ids 和逐段来源，不用一个宽泛时间范围替代多个不连续证据。

默认字幕与 ASR 选择一个经过校验的主文字轨用于正文索引；其他版本/语言可保留并显式参与检索，避免同一内容重复计权。字幕时间有效并不自动代表文字准确或与选定音轨一致，需抽样核对；只提供全文文字的 ASR 适配器不满足时间定位要求，必须增加已验证的对齐能力，否则仅提供真实可用的粗范围并标记定位不完整。

媒体目录继续遵循“只提取结构树”：优先原生章节、真实可见标题及明确的语音章节提示。模型可以辅助确认标题与层级，节点必须关联字幕/语音/画面证据和时间。没有章节时返回空树；按时间分段的播放导航独立显示，不将自动概括的主题名称混入提取目录。

### 16.4 时间来源协议

所有公开媒体时间使用非负整数毫秒，基于对应源文件版本的规范播放时间线；区间采用 [start_ms, end_ms)，时间点采用 timestamp_ms。源容器的原始 PTS、time_base、流起始偏移和规范化规则另存映射，不把编码帧序号、墙上时间或平均帧率当作播放时间。

| 字段 | 约定 |
| --- | --- |
| type | audio 或 video；视频中的语音仍返回 video，打开的是原视频 |
| timeline_id、time_basis | 绑定文件版本的时间线身份；time_basis=source_playback |
| evidence_type | asr、subtitle、frame_ocr、frame_caption、frame_visual、native_chapter 等 |
| start_ms、end_ms | 语句、字幕或已验证连续片段的源时间区间；起点小于终点且不超出已知时长 |
| timestamp_ms、frame_id | 画面证据的实际时间点与帧身份；不能将采样间隔当成画面持续时间 |
| track_id、segment_ids | 所属音轨/字幕轨和真实转写片段；必要时同时记录关联音轨 |
| transcript_version_id、frame_set_version_id | 仅返回当前证据适用的转写或帧集合版本 |
| bbox、coordinate_space | 画面 OCR 可提供相对原始定向画面的归一化区域；转换记录负责裁剪、缩放与旋转回映 |
| precision、mapping_method | time_segment、time_word 或 frame；标明时间戳、经验证对齐或 coarse 等实际方法 |
| mapping_version、preview_version_id | 源文件时间与播放副本之间的映射版本；不存在可靠映射时不声明精确播放定位 |

转换不能默认认为输入输出时间戳完全相同。FFmpeg 的时间戳选项与封装处理可能改变输出时间，快速定位也可能先到前一个可寻址点，因此播放副本需实际核验时间映射，最终定位应解码或等待到目标位置。[FFmpeg 官方文档](https://www.ffmpeg.org/ffmpeg.html)

对可变帧率视频使用真实帧时间戳；对音轨抽取、重采样、ASR 分段、转码和预览剪辑逐层保留映射。静音、空隙、非零起始时间和音视频轨偏移不能被压缩后直接套用旧时间。无可靠时间数据时返回可用的粗范围与原因，不根据文本长度猜时间。

前后播放上下文默认各 2 秒与 3 秒，保存在播放选项中；真正引用区间保持原值。多个不连续命中分别播放，不把二者之间的未命中内容标为证据。播放器完成元数据加载和 seek 后显示实际落点；不允许自动播放时保留定位并显示播放按钮。

### 16.5 搜索、Wiki 与图谱引用

| 需求 | 调用方式与返回 |
| --- | --- |
| 搜录音/视频里说过的话 | mode=keyword/vector/hybrid，filters.media_types=[audio,video]；返回 media_segment、真实语句及时间来源 |
| 搜视频中的字幕或画面文字 | 原生字幕走文字检索；烧录字幕/画面 OCR 走文字检索或 image_text，使用 content_origins 区分来源 |
| 按画面描述或图片找视频 | image_text 检索帧描述；image_vector 检索已建立向量的帧，返回 video_frame、证据图和视频时间点 |
| 搜某个时间窗的内容 | filters.media_time_range={start_ms,end_ms}，按证据时间区间相交或时间点落入筛选；每个文件独立采用自身时间线 |
| Wiki/图谱查到音视频事实 | 返回原 media source_refs，点击打开视频/音频，不能只定位到生成的转写文本 |

content_origin 使用 asr_transcript、subtitle、video_frame_ocr、video_frame_caption 等值；content_origins 为对应筛选数组。按音轨或 speaker_id 筛选时同时限定文档与相应转写版本；无此元数据的记录不假定匹配。搜索返回的 media coverage 与 warnings 说明采样和识别范围，空结果不代表媒体里一定没有相关内容。

语音与画面结果可以汇总到同一文件卡片，但保留独立 hit_id、source_ref_id 和具体证据。多路融合使用相同证据身份去重；时间相邻不意味着语音与画面描述是同一事实。Wiki/图谱沿用默认开启配置，对模型画面描述和转写不确定内容保留标签，不将识别推测改写成已核实原文。

### 16.7 默认配置

继承顺序与全局配置一致：本次覆盖 > 文档覆盖 > 知识库 > 全局默认。以下为初始设计值，任务保存最终快照；资源上限仍以实例硬限制为准。

| 配置项 | 默认值与含义 |
| --- | --- |
| media.enabled | true；音频和视频均正式入库 |
| media.max_file_mib / max_duration_seconds | 2048 / 14400；普通文档默认 2048MiB，上限可独立配置 |
| media.upload_part_mib / upload_session_ttl_hours | 8 / 24；可续传、校验分片与完整文件 |
| media.audio_track | default_or_first_audio；选容器默认轨，否则首个音轨；记录实际选择，可单次覆盖 |
| media.transcript_source | auto；已验证字幕优先，否则 ASR；可选择 asr/subtitle/both |
| media.language | auto，中文词汇提示可配置；转写保留原语言，Wiki 沿用简体中文 |
| media.asr_model_id | 必须绑定实际支持音频与时间戳的模型；不填虚构模型 ID |
| media.timestamp_level | segment；有真实词级结果时保存，不强制所有模型支持词级 |
| media.asr_chunk_seconds / overlap_seconds | 600 / 5；依语音边界及供应商文件/时长限制可进一步缩小 |
| media.chunk_target_seconds | 60；与 512 字符目标共同约束，完整语句及真实来源优先 |
| media.diarization | false；有能力时显式开启，返回匿名标签 |
| media.video_frames.enabled / strategy | true / scene_and_interval；场景变化与间隔采样结合 |
| media.video_frames.interval_seconds / min_scene_gap_seconds | 10 / 1；检测到的场景帧需去重，具体阈值由样本校准 |
| media.video_frames.max_frames | 2000/文件；达到上限保留覆盖信息和截断原因，可按时间窗补处理 |
| media.video_frames.ocr / caption | true / true；使用已有 OCR/视觉模型，模型未就绪时阶段等待配置 |
| media.video_frames.embedding | 继承图片向量开关，默认 false；开启后进入 image_vector |
| media.playback_conversion | auto；优先直接播放，必要时生成已验证编码的播放副本并校验时间映射 |
| media.playback_context_before_ms / after_ms | 2000 / 3000；不改变真实证据范围 |
| media.worker_concurrency / process_threads | 1 / 2；模型并发另外受全局限制 |
| media.process_memory_mib / temp_budget_mib | 2048 / 10240；对子进程及单任务临时产物实际限额 |
| media.process_timeout_seconds / model_request_timeout_seconds | 1800 / 300；可按长文件实际负载调整，超时只重试失败阶段 |

ASR 使用的采样率、声道数和音频编码按适配器能力确定，不能强制所有供应商接受相同格式。分段重叠、临时音频和转换产物计入磁盘预算；原件与最终播放副本的持久化空间另行检查。达到帧/时间/资源预算时显示部分完成及未处理范围，不隐藏缺口。

### 16.8 接口清单

以下路径继续使用 `/api/v1` 前缀与无鉴权公共访问规则。小文件走既有 file/files 上传；大文件走上传会话，但最终创建同一种 knowledge 文档。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| POST | /knowledge-bases/:kb_id/uploads | 创建分片上传会话，绑定知识库与处理配置，返回 upload_id、分片大小、到期时间 |
| GET | /uploads/:upload_id | 查询已接收分片、校验值、总大小与续传状态 |
| PUT | /uploads/:upload_id/parts/:part_number | 流式写入一片；片号从 1 开始，相同校验值重传幂等，不同内容返回冲突 |
| POST | /uploads/:upload_id/complete | 校验片数、大小及完整性，探测实际类型，提交文档与入库任务；重复提交返回同一 knowledge_id/task_id |
| DELETE | /uploads/:upload_id | 取消未完成会话并清理临时分片；已提交文档走原文档删除接口 |
| GET | /knowledge/:knowledge_id/media | 读取媒体格式、时长、音轨/字幕轨、时间线、实际能力与阶段状态 |
| GET | /knowledge/:knowledge_id/transcript | 按文件/转写版本、时间范围、轨道及 cursor 读取语句、词级时间和来源引用 |
| GET | /knowledge/:knowledge_id/frames | 按文件/帧集合版本和时间范围分页读取代表帧、OCR/描述及 source_refs |
| POST | /knowledge/:knowledge_id/subtitles | 绑定配套字幕到指定源文件版本；校验并记录时间偏移，异步生成相应解析/索引版本 |
| POST | /knowledge/:knowledge_id/media/reprocess | 选择 transcription、frames、frame_ocr、frame_caption、alignment 阶段和可选源时间窗重新处理，返回任务 |
| GET / PUT | /settings/media-defaults | 读取和修改第 16.7 节配置，校验模型用途及资源限制 |

媒体读取接口统一接收 file_version_id，必要时附 transcript_version_id/frame_set_version_id；不传版本时只读取当前源文件的适配结果。转写和帧分页绑定版本快照，重处理后旧游标不得混入新结果。重新转写/校准时间后更新受影响的分块与索引，并将旧 Wiki/图谱引用标为待更新；旧引用继续绑定旧版本，不能原地改写时间。

播放复用 `/knowledge/:knowledge_id/preview/manifest` 和内容流，播放副本重建复用 `/preview/rebuild`；manifest 增加 timeline_id、可选音轨、字幕资源、缩略图/波形入口和可用时间映射。`/sources/:source_ref_id` 解析媒体 locator，返回源时间和可用的播放副本时间；第三方可自行渲染播放器。

`/file-formats` 与 `/capabilities` 增加媒体探测、解码、音轨提取、ASR 时间级别、字幕、画面处理、播放转码及时间定位能力。多种封装/编码组合分别报告就绪状态；缺模型不把格式声明为不支持，也不把处理阶段声明为就绪。

分片会话按配置到期清理，完成提交使用幂等状态和持久化任务记录；探测前实行请求及会话大小限制，不能仅凭声明 MIME 绕过普通文件上限。任务状态与进度复用已有任务 API/SSE，提供已转写秒数、已处理帧数与各路覆盖情况。

### 16.9 播放、存储与单容器资源

管理页面与其他项目通过同一公共 API 读取音视频；服务提供正确的内容类型和可用的字节范围读取，播放器按需加载。播放副本默认选择经目标浏览器实测的编码组合，例如 MP4 的 H.264/AAC；可用性由镜像编码器与客户端能力共同决定。原文件保持可下载，副本明确标注来源版本。

音轨片段在 `/data/tmp` 临时保存，处理结束按保留策略清理；版本化转写、字幕、帧证据与时间映射保存于 PostgreSQL 和 `/data/media`，播放副本保存于 `/data/previews`。外部模型只接收该处理步骤需要的音频片段或帧；供应商连接与凭证沿用模型设置。

媒体任务在单应用容器的受监督工作进程中执行，FFmpeg/ffprobe 随镜像提供；任务状态与队列连接固定 PostgreSQL/Redis，ASR/视觉模型沿用外部或宿主机服务。默认单媒体任务避免与本地 OCR/文档解析争抢资源；调度器按实例内存、模型并发及磁盘联合准入。4 核/8GB 仅作为应用容器低并发验收起点，外部中间件资源单独配置，长视频转换需实测。

每个音轨片段、帧窗口和播放副本持久化检查点及配置版本。容器重启后续做未完成阶段；取消任务停止 FFmpeg 子进程和未发出的模型调用，已发出的外部请求按其可用取消能力处理。删除媒体时清理派生产物及索引引用，有其他文档引用的共享资源不能被误删。

### 16.10 首版验收

1. 音频/视频先选择知识库上传，完成转写/字幕和可用画面索引；可通过现有搜索 API 找到文件中的语句与画面文字，Wiki/图谱引用可回到媒体。
2. 点击语句命中后定位对应时间段，显示字幕并支持片段播放；点击帧命中后定位到对应视频时间并显示原帧及可用 OCR 区域。第三方读取同一 source_ref 可以得到一致结果。
3. 覆盖中文、混合语言、背景噪音、静音、无声视频、多音轨、长视频分段边界、重复语句、错位字幕、非零起始时间、旋转视频及可变帧率样本。
4. 对同一引用分别验证原件和转换副本；检查片头、片中、片尾，确保无累计时间漂移。人工标注语句起止与关键画面，报告语句边界误差、播放器实际落点误差、定位成功率及未定位比例；句级、词级、帧级分别统计。
