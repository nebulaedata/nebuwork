# 实时处理流水线

文档页点击“处理流水线”，或在任务中心点击任务名称查看。左侧是可展开的阶段与子步骤，右侧横条表示实际起止时间和耗时。绿色为完成/运行，橙色为待配置，红色为失败；关闭的阶段单独统计。运行中通过 SSE 更新，连接中断时每 5 秒读取快照；文档页摘要每 2 秒更新。

## 按实际引擎显示进度

| 文件与引擎 | 展示方式 |
|---|---|
| PDF / PaddleOCR-VL | 正在处理第 X / N 页；页面响应完成后增加已完成数 |
| PDF / 内置或 Tesseract | 逐页提取文字 / OCR，X / N 页 |
| DOCX / anydoc | 提取内容（引擎无细粒度回调，仅显示耗时）→ 读取原文位置 → 核验 X / N 个内容块 → 提取附件 → 转换预览 |
| DOCX / 内置 | 已处理 X / N 个内容块，同时展示已读取段落数、表格数；生成预览单独计时 |
| Office / LibreOffice | 转换预览文件（无虚构百分比）→ 逐页解析转换副本，明确标注“转换副本” |
| 图片、音视频与后续处理 | 可用时按图片、帧、音频分段、文本分块计数；无法获知总数的转换过程仅显示阶段和耗时 |

DOCX 的原文件通常没有稳定的分页，不使用预览副本的页数冒充 anydoc 或内置引擎的进度。不同阶段工作量不同，不把阶段数或页数折算为虚构的整任务百分比。快速阶段可能直接完成，但仍保留真实时间和计数。

## API

- `GET /api/v1/tasks/{id}`：`checkpoint.pipeline` 包含本次运行的 `run_id`、`attempt`、`started_at`、`finished_at`、`status`、`stages`。阶段具有 `children`、`engine`、`progress`，计数为 `unit/completed/total/current`；内置 DOCX 还有 `paragraphs/tables`。
- `server_time` 用于校正客户端计时；`last_event_id` 用于从快照接续事件。
- `GET /api/v1/tasks/{id}/events?last_event_id=...`：SSE 类型 `task`。收到 `progress: true` 或阶段、状态事件后重新读取任务快照。断线重连支持 `Last-Event-ID`。
- `GET /api/v1/knowledge/{id}/stages`：文档所有任务，可切换查看不同处理记录。

任务结束、失败、取消或中断时停止活动阶段的计时，保留已完成数量。重试获得新运行记录，成功检查点继续复用。旧任务无计时记录时显示已有状态，不补造历史进度。无需数据库迁移，仍使用已有 JSON 检查点与任务事件表。

## 解析内容

解析内容默认渲染 Markdown 和安全 HTML，包括表格和合并单元格。脚本、事件属性及危险链接被移除；文档中的远程图片不自动加载。原始文本仍可切换查看。来源引用按保存的 Unicode 字符位置在原始文本中高亮，防止 HTML 排版改变引用位置。

## 本地更新与验证

在项目根目录执行：

```powershell
docker compose -f compose.dev.yaml build app
docker compose -f compose.dev.yaml up -d --no-deps --wait --wait-timeout 120 app
docker compose -f compose.dev.yaml restart web
```

`19080` 提供镜像内页面与接口；`15173` 是 Vite 开发页面，重启会安装新增的前端依赖。现有解析内容刷新页面后即可使用排版视图；流水线计时从更新后的任务运行开始记录。

测试：`tests/test_progress.py` 校验真实解析器计数，`tests/pipeline_progress.py` 在独立的 19081 测试服务验证逐页进度、SSE、DOCX、取消、重试和失败，`web/tests/parsed-content.mjs` 校验表格、HTML 清理与 Unicode 来源高亮。隔离测试的 Paddle/模型响应是明确的协议夹具，不代表实际 OCR 识别质量。
