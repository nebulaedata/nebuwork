# 模型与解析设置

## 服务连接管理与模型用途

在「设置 → 模型 → 服务连接管理」新增连接，填写连接名称、基础 URL、API Key。Key 加密保存，列表只显示是否已设置；已有模型的连接在升级时自动迁移，不需要重新输入。原模型 ID、地址、模型名称、用途和有效凭证保留。

添加模型时，通过「基础地址 / 服务连接」选择已保存连接；页面显示正在使用连接凭证，查询模型列表和实际调用均由后端自动带上 Key。也可以在添加模型弹窗里直接点「新建连接」，保存后自动选中。需要单独配置时切换为「手动填写地址与 Key」。

服务连接支持新增、编辑、查询模型和删除。地址或 Key 修改后，所有引用模型的后续请求使用新值；正在执行的请求不会被强制中断。正在被引用的连接禁止直接删除，应先为模型更换连接。变更带密钥的地址时须重新填写 Key 或明确清除，防止误把旧凭证带到另一个地址。变更向量模型的地址后，原向量索引保留，检索会要求匹配当前模型配置的索引。

“编辑模型”的用途可以修改。保存时会在同一事务内更新模型，并清理全局、知识库、文档与未完成任务中不再匹配的旧用途绑定，不自动占用新用途。原文、分块、索引保留；缺少必要绑定的阶段明确等待配置，重新绑定后可继续。任务重试也会检查旧快照中的模型用途，避免误用模型。

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET / POST | `/api/v1/model-connections` | 查询 / 新增服务连接 |
| GET / PUT / DELETE | `/api/v1/model-connections/{id}` | 查看 / 编辑 / 删除连接 |
| POST | `/api/v1/models/discover` | 传 `connection_id`，使用保存的地址与 Key 查询模型 |
| POST / PUT | `/api/v1/models`、`/api/v1/models/{id}` | 传 `connection_id` 关联连接；`purpose` 可编辑 |

模型编辑请求省略 `connection_id` 时保留原连接，显式传空字符串时改用手动配置。选择连接时不接受同时覆盖 Key；连接凭证不会通过接口回显。连接查询返回 `has_api_key`、`model_count`，模型查询返回 `connection_id`、`connection_name` 和有效地址。模型保存响应的 `purpose_changed` 表明是否清理了不匹配的绑定。

## 模型快速选择

### 文本生成与目录核验混用

「默认用途绑定」的文本生成、目录核验两个下拉框都列出这两类模型，选项附带用途名称，便于区分同名模型。可以交叉选择，也可以两项选择同一个模型，无需为了另一个用途重复添加模型。后端绑定校验、任务配置检查、实际文本生成和目录处理使用同一兼容规则；向量、视觉、ASR、重排等其他用途仍各自匹配。

目录核验未绑定时继续继承文本生成绑定；文本生成仍需明确选择模型。模型用途在「文本生成 ↔ 目录核验」之间切换时，保留已有的两个用途绑定；改成不兼容用途时才清理对应绑定。更新不会自动改动现有用户选择。

`tests/model_purposes.py` 在隔离环境验证交叉绑定、同一模型用于两项、目录留空继承、实际 Wiki / 目录模型调用、兼容用途切换时保留绑定，以及未完成任务恢复。

### 文本生成的图片输入

添加或编辑「文本生成」模型时，可设置「允许图片输入」，默认关闭；已有模型没有该字段时也按关闭处理。列表以「仅文本 / 允许图片」标识区分，开关不会根据服务模型名称自动推断，也不会修改模型用途或默认用途绑定。请根据实际模型能力开启。

接口字段为 `config.allow_image_input`（布尔值），随模型新增、编辑、列表、详情保存与返回。后端会在发送聊天图片前检查该配置，关闭时返回 `IMAGE_INPUT_DISABLED`，不向上游提交图片。开启后的「测试」入口可分别进行文字测试、上传图片测试；`POST /api/v1/models/{id}/test-file` 接受 PNG、JPEG、WebP 图片（最大 20 MiB），`POST /api/v1/models/{id}/test` 保持文字测试。视觉理解用途仍按原有方式接收图片；切换到其他用途会移除文本模型的图片输入开关。

保存开关表示允许发送图片，实际图片理解能力以服务和样本测试结果为准。隔离验收命令为 `python tests/model_image_input.py`，使用下文相同的测试部署与 `NEBULAEKNO_TEST_API_URL`。

### 查询服务模型列表

在「设置 → 模型 → 添加 / 编辑模型」选择服务连接（或手动填写基础地址和 API Key），点击「查询模型」，再从可搜索的下拉框中选择模型名称。服务不支持列表查询时，可以输入模型标识后按回车。

基础地址为服务根地址时查询 `/v1/models`；已有 API 前缀时在其后追加 `/models`。编辑已有模型时，密钥留空会使用已保存凭证；更换服务地址后需要重新填写密钥，不会把旧密钥发送给新地址。模型用途仍由用户选择。

接口：`POST /api/v1/models/discover`，请求字段 `base_url`、`api_key`，复用连接时传 `connection_id`，手动配置编辑时还可传 `id` 和 `clear_api_key`；返回规范化的 `base_url` 与去重排序后的 `models` 名称数组。凭证不回显。

## 解析设置入口

全局设置拆成三个独立页签：

| 页签 | 内容 | 保存范围 |
| --- | --- | --- |
| 文件格式与引擎 | 每种文件格式一行，选择解析引擎、恢复默认引擎 | 只保存 `parser_engines`，不提交其他页的修改 |
| 解析引擎配置 | PaddleOCR-VL 服务地址、印章与图表识别、连接检查；内置引擎说明 | 保存全局服务配置，所有知识库共用 |
| 解析策略 | 分块与内容、音视频处理、图片解析、知识图谱与目录四个分组 | 保存处理策略，不覆盖格式引擎选择 |

各页独立保存；在当前设置页内切换页签会保留未保存的修改，刷新或离开设置页前请保存。文件类型列表单独滚动，顶部导航和保存按钮保持可见。

页面截图：[文件格式与引擎](screenshots/parser-format-settings.png)、[解析引擎配置](screenshots/parser-engine-settings.png)、[解析策略](screenshots/parser-strategy-settings.png)。

每个知识库在创建弹窗或「知识库设置」中分为「文件格式与引擎」「解析策略」两个页签，随知识库一起保存。服务连接在全局统一管理。全局默认值用于新建知识库，已有知识库保留自己的配置；配置在任务创建时保存快照，修改后用于新上传或重新处理，已有结果不会被直接改写。

每种文件类型单独一行、独立保存，下拉选项由后端统一目录返回。与截图相同的一组扩展名（例如 DOC/DOCX）共用一行；音频、视频分别配置，DOCM、ODT、ODS、ODP、RTF 等各自成行。

| 文件类型 | 默认引擎 |
| --- | --- |
| PDF、图片 | PaddleOCR-VL |
| Word、演示文稿、Excel、EPUB | anydoc |
| DOCM、ODT、ODS、ODP、PPTM、RTF、XLSM | anydoc |
| OFD、MHTML/MHT、Markdown、HTM、HTML、XMind | 内置 |
| CSV、TXT、JSON、音频、视频 | Simple |
| TSV、XML、YAML、日志及代码文件 | Simple（各自独立一行） |

“Simple” 是本地轻量解析路径；音视频使用 FFmpeg 提取媒体并调用绑定的 ASR 模型转写，不代表无需语音识别模型。PDF 可选内置/Tesseract，图片可选 Tesseract，Office 可选内置或 LibreOffice，CSV 可选 anydoc。

升级迁移会拆开旧分组，升级全局原厂默认值；已有知识库保留曾保存的引擎选择并补齐新增类型。“恢复默认引擎”只重置当前表单中的引擎选择，点击保存后生效，不改图片要求、图谱要求及其他参数。历史文件和运行中任务不自动重解析。

## anydoc

应用镜像实际安装 [官方 firecrawl-anydoc](https://github.com/firecrawl/anydoc/tree/main/python) **0.2.4**（Rust 内核、Python 绑定），直接在受监管的解析子进程执行，无需额外服务或模型。启动健康检查会实际转换 CSV 验证可用性，`GET /api/v1/parser-engines` 返回版本与可用状态。不会启用远程托管 OCR。

anydoc 提取文档结构、正文、标题、表格与内嵌图片；对 DOCX/PPTX/XLSX/EPUB，另用原生读取器核验来源位置。只有唯一匹配时才使用段落、幻灯片或单元格定位；重复内容或无法匹配时标记文件级位置，并支持跳转解析片段，不虚构页码。Office 预览仍使用 LibreOffice 转 PDF。

OFD 内置解析目前支持文本层及原始页码，扫描型 OFD 明确报 `OFD_NO_TEXT_LAYER`；尚不提供 OFD 原版面渲染。MHTML 提取归档 HTML 正文；XMind 支持 JSON/XML 结构树和节点标识。GIF 使用首帧，其他帧不作为视频解析。

「解析策略 → 图片解析」配置内容理解、图片向量开关和自定义图片描述要求；描述要求也用于视频代表帧。图片与视频画面描述均需视觉模型。OCR 文本与生成描述分别保留。

「解析策略 → 知识图谱与目录」配置目录、Wiki、图谱开关，以及实体类型、关系类型、抽取要求和示例。中文通用配置保持默认开启，示例不作为事实入库。

新字段：`parser_engines`（每个键对应独立类型，完整键名、默认值与选项见 `GET /api/v1/parser-engines` 的 `formats`、`defaults`、`choices`）、`image_instructions`、`extract_config.tags`、`extract_config.relations`、`extract_config.custom_instructions`。保存至 `PUT /api/v1/settings/parser-defaults` 或知识库 `config`。音视频参数合并在 parser-defaults 的读写接口，原 `media-defaults` 接口保持兼容。

## PaddleOCR-VL 连接

在「设置 → 解析引擎配置」中填写完整 Pipeline 服务基础地址，例如 `http://host.docker.internal:端口`，点击「检查连接」和「保存引擎配置」。连接配置存于 `PUT /api/v1/settings/parser-engines` 的 `paddleocr_vl` 对象，包含 `endpoint`、`use_seal_recognition`、`use_chart_recognition`。

该服务必须支持 [PaddleOCR-VL 的 `/layout-parsing` 协议](https://www.paddleocr.ai/v3.6.0/en/version3.x/pipeline_usage/PaddleOCR-VL.html)，只有 `/v1/chat/completions` 的模型服务不能直接替代。健康检查只验证 `/health`；实际解析能力以文件处理结果为准。

应用镜像包含调用适配器，不包含 Paddle GPU 模型权重或推理服务。未填写地址时使用该引擎的 PDF/图片任务进入 `waiting_configuration`，错误码 `PARSER_NOT_CONFIGURED`；保存连接后自动恢复。也可以为知识库选择本地引擎，再重新处理文件。

PDF 逐页提交，保留文件版本、页码和可用的版面区域坐标；预览支持区域高亮。文字未提供合法框时保留页级定位；图片必须有合法区域坐标才能裁剪，否则解析失败并提示检查服务，不使用整页图替代。

## AI 生成图片与图谱要求

「解析策略 → 图片解析」的内容理解要求旁增加 **AI 生成**；「知识图谱与目录」的图谱抽取配置旁也提供同一入口。全局默认设置、创建知识库、已有知识库设置均可使用。

填写资料类型与处理目标，或点击「使用通用场景」，可选择是否参考当前填写的内容。图片生成内容理解要求；图谱生成实体类型、关系类型、抽取要求与虚构示例。结果先在弹窗中预览并允许编辑，图谱可逐项勾选要填入的字段。点击「填入当前表单」仅修改草稿，再保存策略或知识库才生效。取消、关闭、生成失败不会改写现有配置；生成中可停止。

生成使用 **文本生成用途绑定** 的模型，兼容 text 与 outline 类型。全局设置和新建知识库使用全局绑定，已有知识库优先使用自身绑定。这里只生成文字要求，不需要图片输入能力；实际图片解析仍使用图片解析流水线及视觉模型。仅发送所填目标和勾选参考的当前要求，不自动读取或上传知识库文件。

接口：`POST /api/v1/processing-config/suggest`。

```json
{
  "kind": "graph",
  "context": "企业设备和项目资料，关注设备、组织、项目之间的关系",
  "current": {
    "extract_config": {
      "tags": ["设备", "组织", "项目"],
      "relations": ["负责", "使用"]
    }
  }
}
```

`kind` 为 `image` 或 `graph`；`context` 为 1–4000 字。`current` 可省略，图片时只接受 `image_instructions`，图谱时只接受 `extract_config` 下的 `tags`、`relations`、`custom_instructions`、`text`。可传 `knowledge_base_id` 使用该知识库模型绑定。响应包含 `suggestion`、不含凭证的模型标识和 `saved: false`。未配置模型返回 422，调用失败或生成结构不合规返回 502；不会返回模拟成功或自动写入配置。

隔离验收：`NEBULAEKNO_TEST_API_URL=http://127.0.0.1:19081/api/v1` 下执行 `python tests/processing_suggestions.py`。测试桩验证真实请求、绑定、错误处理和不自动保存；实际生成内容质量取决于接入模型。页面示例：[图片要求预览](screenshots/ai-image-suggestion.png)、[图谱字段选择](screenshots/ai-graph-suggestion.png)，均为隔离协议验收截图。

实际浏览器已验证生成结果可编辑、填入后尚未保存、按勾选保留原字段、保存生效、未绑定提示、停止后不接收晚到结果，以及知识库弹窗使用自身模型绑定。已部署入口见 [AI 生成按钮](screenshots/ai-generation-entry.png)。Go 测试、`go vet`、TypeScript 检查与容器构建通过；开发环境原模型、绑定、解析配置和知识库保持不变。

## PDF 版面区域与图片（2026-10-23）

PDF 按扫描页面送入 PaddleOCR-VL Pipeline，显式开启 `useLayoutDetection`、`useOcrForImageBlock`，关闭方向旋转及去弯曲以保持坐标一致。按照返回的阅读顺序保留区域类型、原始标签、block_id/block_order、页码与归一化 bbox。

- 文字及标题：OCR 正文按分块设置处理，不附带页面截图。
- 表格：保留完整结构块及 HTML 合并单元格，不按字符数切断标签；这种结构块可能超过普通文本分块长度。
- 图片、图表、印章及页眉页脚图片：按版面框从本地原页栅格图裁剪，单独保存为 image 资源。图题仍作为文字保存，不按相邻页或相邻块猜测图片归属。
- 裁剪图的提取内容与视觉模型生成的描述分开保存；图片理解及图片向量索引只接收实际图片资源。没有图片的页不会产生整页图片理解任务。
- PDF 栅格图登记为 pdf_page / page_preview，仅供原文预览；图片列表、分块图片、图片检索均不返回整页图。大于等于 98% 页面面积的图片区域按整页处理，跳过图片理解并给出页面提示。
- 缺少版面区域列表或图片坐标无效时明确失败，不降级为整页图片理解；独立上传图片、DOCX 内嵌图片和视频代表帧保持各自处理方式。

文档“图片与解析”可查看裁剪图、区域 OCR/图表识别结果及 AI 描述；“分块”显示文字/表格/图片类型与页码，仅在确实引用图片的块中显示图片。点击定位可回到原 PDF 页并高亮区域。来源始终绑定文件版本与解析版本。

升级保留旧文件和历史来源 ID，已有整页图及其生成描述退出图片展示和检索。旧 PaddleOCR PDF 的 content 接口返回 requires_image_reparse=true，页面提示点击“重新处理”；不会自动批量调用模型。旧的 Wiki/图谱等生成结果需要重新处理相应文件才能更新。

## Wiki 来源编号与批次重试（2026-10-23）

每批仍使用 16 个完整分块，保持当前文本模型、温度及 Wiki 配置。发送给模型的材料只将长来源 ID 映射为本批的 `S1`、`S2` 等编号，同一来源的多个分块共用一个编号；原始正文不裁短。模型返回的来源列表及正文 `[来源](source:S1)` 都须校验，保存时还原为真实 `source_ref_id`，保留文件版本、页码、区域等原文定位。

每批首次请求失败后最多自动重试 2 次（总共 3 次）。引用/JSON 错误会把具体校验反馈和完整原材料重新发给相同模型；网络暂时错误按 2 秒、4 秒退避。认证等不可重试错误直接标记失败。不会删除错误引用、放宽来源检查、切换低能力模型或通过缩短材料来制造成功结果。来源校验能保证引用对应关系，不代替对模型事实表达质量的人工评价。

整批所有页面校验通过后，页面、修订与成功检查点在同一个 PostgreSQL 事务中保存。失败不会留下半批页面；某批耗尽预算后继续处理后续批次。成功批次不重复调用模型或写修订；停止容器后使用持久化检查点恢复，已发出的中断请求计入本轮预算。

文档或任务的“处理流水线”显示批次成功/失败数、“第几批 · 重试几/2 · 已保存分块数”；“批次详情”提供分块范围、轮次与错误历史。点击“仅补跑失败批次”，只运行 Wiki 并对未完成批次开启新一轮预算，已成功批次、原解析及其他阶段保持。其他阶段尚有失败或待配置时，整个任务仍如实显示该状态。

API：`POST /api/v1/tasks/{id}/wiki/retry-failed`，无请求体；`GET /api/v1/tasks/{id}` 的 `checkpoint.wiki_batches` 与已有 SSE 提供实时更新。运行中、已完成、旧解析版本拒绝提交；材料或 Wiki 配置发生变化时拒绝混用历史批次，应重新处理文档。旧任务没有可靠批次检查点，界面明确显示“重试 Wiki”，首次重试会重新生成 Wiki 并开始记录；不会自动批量重建现有文档。

隔离验收：`tests/wiki_batches.py` 覆盖来源列表/正文错误、两次自动重试、批次原子保存、后续批次继续、只补跑首个失败批次、完整材料不变、历史修订保留、来源定位、容器中断恢复与旧任务兼容。测试使用独立协议测试桩，不向开发环境写入模型或文档。

已完成开发容器更新与配置摘要核对；实际浏览器验证了失败批次补跑、自动更新及错误记录展开。[隔离验收：批次补跑结果](screenshots/wiki-batches-completed.png)。


## Wiki 页面关系图与实体知识图谱（2026-10-23）

知识库「Wiki」提供「页面阅读 / Wiki 页面关系图」切换。Wiki 图的节点是文章，箭头是文章之间的引用；实线表示 `[[页面标题]]` 或 `[标题](wiki:页面ID)`，虚线表示「关联页面 / 相关页面」章节中的明确页面列表（纯标题、加粗标题或 `[标题](#)`）。只匹配本知识库中已存在的页面，不根据共用来源、相似词或模型猜测补造关系。忽略代码示例和 HTML 注释，未匹配引用只统计数量；未关联页面仍可筛选查看。页面目录不再限制为前 100 页，正文按所选页面加载。

图中可以搜索定位、缩放拖动、筛选已关联/未关联页面、查看出入链接，双击节点或点击「打开 Wiki 页面」进入正文。页面编辑、修订恢复或删除后，关系从最新内容重新读取；刷新图无需重新生成文章或调用模型。原 Wiki 正文、生成质量要求、来源编号、批次重试和证据定位保持。

「实体知识图谱」为独立标签，节点为从原文抽取的人物、组织、设备、概念等实体，边为有原文证据的事实关系，继续使用现有 Neo4j 数据和 `/graph` 接口。

- `GET /api/v1/knowledge-bases/{id}/wiki/graph`：兼容原数组形式，返回实时页面关系（source_id/target_id/source_title/target_title/kind）。
- 同一路径 `?view=overview`：返回 `nodes`（id/title/state/folder_id/updated_at，不含正文）、`edges`、`unresolved_references`。包含未关联页面，不以文章分页截断。
- `POST .../wiki/rebuild-links`：按相同规则重建派生关系索引；正常浏览无需先调用此接口。
- `GET .../wiki/stats` 的 links 与实时关系一致。

验收：`tests/wiki_graph.py` 仅连接 19081 隔离环境，覆盖跨库隔离、页面增删改/修订恢复、索引重建、超过 100 页及实体图数据独立性。
