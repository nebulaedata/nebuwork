# 知识库问答

左侧「知识库问答」入口为 `/qa`，会话地址为 `/qa/{id}`。先选择知识库，可进一步限定文档，再发送问题。支持连续追问、会话重命名、删除、停止和重试。会话共享公共工作空间，沿用现有无登录接口。

## 每轮处理

加载最近 8 轮同范围的完整对话 → 补全问题中的指代 → 关键词、向量、图片文字召回 → 融合去重与自动重排 → 补充相邻分块和可靠关联的原图 → 读取图片 → 流式回答 → 校验引用并保存。

默认候选 50 条、证据 10 条、最多 4 张原图、证据文字预算 24000 字。Wiki、图谱可在会话设置中启用。未就绪通道和未配置重排会提示；全部通道失败与检索无结果是不同状态。问题改写失败时使用原问题。历史仅帮助理解指代，当前答案仍依赖本轮检索；修改范围后不会带入旧范围的证据。

## 提示词和模型

「设置 → 知识库问答」维护全局系统提示词、回答模型和图片理解模型。会话设置可覆盖提示词，留空或设为 `null` 恢复沿用全局。全局和会话修改影响后续提问，每轮保留实际提示词与模型配置快照，不保存或回显模型密钥。重试使用当前配置创建新记录。

`GET /api/v1/settings/qa-defaults` 返回 `system_prompt`、`model_id`、`vision_model_id`，另有只读的 `default_system_prompt` 供恢复默认使用。`PUT` 接受前三项，支持合并更新。模型 ID 为空时分别沿用系统 `text`、`vision` 绑定。提示词最多 16000 字。服务端追加引用协议，使自定义提示词与引用、原图展示相容。

回答模型是已启用图片输入的文本模型时，直接传入原图。否则先调用图片理解模型，再由文本模型依据文字、原文证据和图片解读回答。没有可用读图模型或读图失败时，明确提示未读图，保留已有 OCR、描述和原图。独立图片解读只属于本轮，不改写文档内容或索引。

## 原图与引用

只使用入库原图与真实分块/单元格关联，不按同页位置猜配图片。来源和图片同时绑定文档、文件版本、解析版本。模型使用 `[1](source:来源UUID)` 和 `![原图](asset:图片UUID)`，服务端校验本轮 ID，前端只允许这些已提供的引用和图片，禁止模型自行构造外部图片地址。

点击引用或图片的「定位原文」在新标签页打开已有预览链接，保留问答页面。按原有能力定位到页码/区域、文本、单元格、媒体时间。无法精确定位和转换后位置沿用明确标识；模型读图结果不当作逐字原文。

重解析不会改变历史问答的版本。历史消息的 `sources`、`images` 为冻结快照，`available=false` 表示原来源/资产已删除或不再匹配，不能套用新版本。图片文件不可读时页面显示不可用。

## 接口示例

以下路径以 `/api/v1` 为前缀，响应沿用 `{success,data}`；错误为 `{success:false,error:{code,message,retryable}}`。列表 `meta` 含分页，默认 20、最多 100 条。会话按更新时间倒序，消息按创建时间倒序。

```http
POST /api/v1/qa/sessions
Content-Type: application/json

{"knowledge_base_ids":["KB_UUID"],"knowledge_ids":[],"system_prompt":null,"enable_wiki":false,"enable_graph":false}
```

返回 201，会话 `id` 用于后续请求。可用 `PATCH /qa/sessions/{id}` 修改标题、范围、提示词和增强选项。范围最多 100 个知识库、1000 篇文档，文档必须属于所选知识库。`DELETE` 删除会话及其消息、事件，不删除知识库文件。

```http
POST /api/v1/qa/sessions/SESSION_UUID/messages
Content-Type: application/json
Idempotency-Key: caller-unique-key

{"query":"这款接入箱的安装要求是什么？"}
```

返回 202，`data` 含 `user_message_id` 和 `assistant_message_id`。问题最多 4096 字。相同会话、幂等键和问题返回原消息 ID；不同问题复用键返回 409。同会话同时只执行一轮，否则返回 `QA_BUSY`。

通过 `GET /qa/messages/{assistant_message_id}/events` 接收持久化 SSE：

| 事件 | 数据 |
| --- | --- |
| `stage` | `{stage}`，当前阶段 |
| `warning` | `{message}`，降级或配置提示 |
| `evidence` | `{sources,images,rewritten_query}` |
| `delta` | `{delta}`，追加答案文本 |
| `done` | 终态及最终答案/证据/错误；若有 `content`，替换已拼接文本 |

事件包含递增 `id`，使用 `Last-Event-ID` 请求头或 `last_event_id` 查询参数续接。浏览器断开不停止模型，不会因重连重复生成。最终引用校验可能移除非法标记，客户端应采用终态答案并刷新历史消息。

`GET /qa/sessions/{id}/messages` 查询历史。`POST /qa/messages/{id}/stop` 停止生成，保留已生成内容；排队中的消息立即取消。`POST /qa/messages/{id}/retry` 创建新的用户/回答记录，原记录和 `retry_of` 保留，也支持幂等键。状态包括 `queued/running/completed/failed/cancelled/interrupted`。流中断或空回答不能当作完成；服务重启后过期运行租约标为 `interrupted`，不自动再次调用模型。

## 验证

Go 单元与竞争检查：`go test -race ./...`、`go vet ./...`。前端：在 `web` 执行 `npm run build`。

隔离协议集成测试先构建 `nebulaekno:qa-test`，然后执行：

```powershell
docker compose -f tests/compose.yaml -f tests/compose.qa.yaml up -d --wait --wait-timeout 180 postgres graph redis app
docker run --rm --name nebulaekno-qa-runner --network nebulaekno-qa-test_default -e NEBULAEKNO_QA_TEST_URL=http://app:8080/api/v1 -e NEBULAEKNO_QA_TEST_DATABASE_URL=postgresql://nebulaekno:integration-only@postgres:5432/nebulaekno?search_path=nebulaekno,public -e NEBULAEKNO_QA_FIXTURE_URL=http://nebulaekno-qa-runner:9000 -v "${PWD}:/src" -v nebulaekno-qa-test_data:/data -v nebulaekno-gomod:/go/pkg/mod -v nebulaekno-gobuild:/root/.cache/go-build -w /src golang:1.26-bookworm go test -run TestKnowledgeQAIntegration -v ./internal/api -count=1
```

测试只使用 `nebulaekno-qa-test` 网络、数据库和文件卷，以及显式 HTTP 模型协议桩，不验证真实模型的理解准确率。页面验收地址为 `http://localhost:19083/qa`。测试结束可对相同 Compose 文件执行 `down`，不会影响开发服务或删除卷。
