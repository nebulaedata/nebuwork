# 运行场景与输入说明

工作流定义可选包含 `input_presets` 数组，每项为 `id`、`name`、`description`、`input` 和 `fields`。第一项为默认场景，`fields` 使用 JSON Pointer 指向输入中的字段并保存中文说明。参数路径必须存在；嵌套对象、数组、空对象及标量均受支持。

独立页面通过“运行场景”编辑并应用到流程草稿，然后使用页面顶部“保存流程”。创建任务时自动填入首个场景的 JSON，用户可切换、修改或恢复预设。修改仅用于本次运行，每个场景在当前窗口中保留自己的草稿。没有预设的流程继续使用自定义 JSON，不批量补齐。

构建助手和 MCP 指南要求根据实际业务代码生成完整输入与逐项说明并保存至定义；仅构建请求不运行任务。不要把示例场景作为所有工作流的固定模式，也不要编造业务参数。

定义校验、源码保存、复制、历史恢复与任务快照均保留预设。运行 API 不变，仍只提交最终 `input`。创建及启动分别复用原命令标识、输入和版本来处理响应丢失。

与 NebuWork 共用的 `frontend/src/inputPresets.ts`、`InputPresetControls.tsx` 和 `inputPresets.css` 需同步维护。组件与工具文件使用不同主文件名，避免 Windows 模块解析时大小写不敏感导致导入冲突。完整交付、升级顺序及验收说明位于 `D:/Work/Code/AiCode/NebuWorkAgent/docs/workflow-input-presets-delivery.md`。先更新支持新定义的服务，再更新客户端；无数据库迁移，不自动补齐历史业务流程。
