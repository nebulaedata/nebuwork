# 法律法规原文件增量采集

## 默认一键使用（已变更）
入口 collect -> all_categories.py:run。创建任务选择默认“一键全分类续采10份（真实运行）”，无需修改分类或参数，输入 {} 即真实联网。
自动读取官方全部一级分类（宪法、法律、行政法规、监察法规、地方法规、司法解释），各分类查询包含其全部子分类；按条目轮转，跨任务保存分类位置、分页与页内偏移。
每批目标新增10份此前未成功的不同内容文件，历史下载记录沿用不清空。成功条目按 bbbs 跳过，同 SHA256 内容不重复计入10份。不是每类10份，也不是每批必须覆盖每个细分类；持续运行逐步遍历。
再次点击创建并运行新任务，输入仍为 {}，沿用共享索引继续。不要重置或并发运行任务。
自动模式不重新检查成功条目的静默修改；源站分页动态变动可能使偏移发生变化，扫到末尾后回到首页可再次扫描遗漏新条目，不保证实时完整性。

## 产物
每批下载成功的 original_<SHA256>.<扩展名> 同时保存至任务和共享产物；额外提供“本批法律法规原文件.zip”，内部采用法规中文标题和条目标识命名，附文件索引.json。
file_index 保存标题、分类、来源、哈希和产物名；audit 保存 downloaded、skipped、failed、duplicate_content、requests、target_met、stopped 和进度。任务 succeeded 不等于一定下载10份，必须看审计。
共享索引 npc_incremental_state_v1；新增 all_categories_v1 子状态，不覆盖历史分类游标与原文件。旧文件不会删除。

## 可选场景与兼容
默认模板 {}：全分类真实续采，目标10份。
全分类不联网演练可输入 {"dry_run":true}。
历史三个模板保持原 ID 和输入：不联网演练、宪法小批量、附件复查。显式 categories 时转入 npc_incremental.py 旧实现，max_documents 仍为1～3，每次一个指定分类的一页；没有 categories 时为新全分类模式，max_documents 范围1～10且默认10。
不要在默认全分类模板中添加 categories；不需要自己提供 URL、正则或邮箱。

## 限制与访问
共享环境，仅标准库。工具 UA，每次请求间隔至少15秒，全分类批次最多80次请求，单文件20 MiB，无自动重试和重定向，HTTP超时35秒，步骤超时3600秒。
只允许已核实的官方 HTTPS 主机 flk.npc.gov.cn、flkoss.obs-bj2.cucloud.cn。按用户委托不读取 robots；此前 robots 明确禁止自动采集，此设置不是网站授权或合规保证。登录、验证码、访问拒绝不绕过，任何下载异常停止本轮，保留未完成游标。
当前通过官方 docx 下载接口获取文件，检查 DOCX ZIP CRC及word/document.xml（也支持识别PDF/DOC容器），不将网页转换成原附件；不代表人工内容或法律效力核验。
请求失败、附件缺失、扫描完毕或预算用尽可能少于10份，不拿重复文件、失败条目凑数。
禁止并发：共享状态无CAS锁。步骤成功才发布本批状态与文件；进程异常终止时未发布进度可能需重做，不支持字节级断点续传。未配置定时调度。
旧 incremental.py/listing.py/law_http.py 等仅保留历史实现，不接入默认入口。
